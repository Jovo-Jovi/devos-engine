equivalence: the Tower's own settings, expressed as a project file, regenerate the Tower's configuration exactly.

#### Steps

- **S1 — `payload/files/devos/engine.defaults.json`** = `dev/sources/tower/devos.config.json` with exactly three
  changes: the top-level `project` key removed; `screens.pages` set to `["/"]`; `src/lib/contract/**` and
  `src/app/api/**` removed from `reviewer.deep_paths` (16 entries remain, the pilot's list). Every other key, value,
  comment and key order unchanged. 2-space JSON, LF, final newline.
- **S2 — `payload/templates/devos/project.json`:** `$comment` (one sentence: this file is yours; `devos.config.json`
  is generated from `devos/engine.defaults.json` and this file; edit here, then run
  `node scripts/devos/config.mjs --write`), `project` `"__PROJECT_KEY__"`, `scenario` `"new"`, `screens`
  `{ "pages": ["/"] }`, `reviewer` `{ "deep_paths_extra": [] }`.
- **S3 — `payload/files/scripts/devos/config.mjs`** (dependency-free, uses `ROOT` and `P` from `./lib.mjs`). Exports
  `merge(defaults, project)` and `build()` (reads both files, returns the merged object). Merge rules:
  1. plain objects merge recursively; a project scalar or array **replaces** the default;
  2. a project key `<name>_extra` whose value is an array **appends** to the merged `<name>` array; if `<name>` is not
     an array in the defaults, `merge` throws `config: <path>_extra needs an array <path>`; the `_extra` key is not emitted;
  3. a project value `null` removes the key;
  4. project keys that start with `$` are never merged;
  5. output key order: `$generated` first, then the defaults' order, then keys only the project has.
  `$generated` = `"Generated by scripts/devos/config.mjs from devos/engine.defaults.json and devos/project.json. Edit
  devos/project.json, never this file (PR-39)."`. CLI: `--print` writes the merged JSON to stdout; `--write` writes
  `devos.config.json` (2-space, LF, final newline) and prints `devos.config.json written (<n> top-level keys)`;
  `--check` exits 0 printing `devos.config.json is current` when the file deep-equals `build()`, else exits 1 naming the
  first differing key path. Missing `devos/project.json` → exit 2 `no devos/project.json: nothing to generate`.
- **S4 — `payload/files/scripts/guards/config.mjs`** (default export, returns `result(...)` from `./lib.mjs`):
  `N/A` with note `no devos/project.json (configuration not split)` when that file is absent; `FAIL` when
  `devos/engine.defaults.json` or `devos.config.json` is missing, or `devos.config.json` does not deep-equal the merge,
  with the finding `devos.config.json is not devos/engine.defaults.json ← devos/project.json (first difference: <path>)
  — run node scripts/devos/config.mjs --write`; otherwise `PASS` with note `generated config is current`. Import the
  merge from `../devos/config.mjs`; do not duplicate it.
