#### Steps

- **S1 — Home.** A developer file lives under `<home>/.devos/`. `<home>` is `process.env.DEVOS_HOME` when that variable is a non-empty string, otherwise `os.homedir()`. Never read or write the real home in a test: every test sets `DEVOS_HOME` to an empty temporary directory.
- **S2 — Profile** (`lib/profile.mjs`, command `devos profile`). The file is `<home>/.devos/profile.json`. It holds
  choices only, never a credential (PLAN §4). Keys allowed, with their value rules: `github_owner` (string,
  `^[A-Za-z0-9-]{1,39}$`), `visibility` (`private` or `public`), `default_stack` (string), `cursor_accounts` (`1` or
  `2`, stored as a number), `claude_accounts` (`1` or `2`, stored as a number). No other key. A value outside its rule
  prints `devos: profile <key> must be <rule>` and exits 1 without writing. `devos profile show` prints the file as JSON, two-space indent, one trailing newline. Missing file prints `{}` and the same newline, and exits 0. `devos profile set <key> <value>` writes that one key. A value that matches `/\b(ghp_|gho_|github_pat_|sk-|AKIA[0-9A-Z]{8})|-----BEGIN /` is refused (the `\b` keeps
  ordinary words such as `task-runner` allowed; a test proves both): print `devos: profile refused a value-like string`, exit 1, and do not create or modify the file. An unknown key prints `devos: profile key <key> is not allowed` and exits 1.
- **S3 — Roster** (`lib/roster.mjs`, command `devos agents`). The file is `<home>/.devos/roster.json`. Shape:
  - `reviewer`: `{ "id", "tool", "model" }` with `tool` one of `cursor` or `claude`
  - `reviewer_light`: the same object, or `null`
  - `pool`: an array of `{ "id", "tool", "model", "default", "note" }`. `default` is boolean. Exactly one item has `default: true`. `note` is a string and may be empty. `tool` is `cursor` or `claude`.
  - `policy`: `reviewer-picks` or `always-default`
  `devos agents import <file>` reads that JSON, checks the shape, and writes the canonical file (`JSON.stringify(value, null, 2)` plus one newline, keys in the order above, pool order unchanged). A bad shape prints `devos: roster <reason>` and exits 1 without writing. `devos agents show` prints the canonical file. Missing file prints `devos: no roster` and exits 1.
- **S4 — Detect.** New `lib/which.mjs` exports `which(cmd)` → `{ path, viaShell }` or `null`, resolving the command
  itself from `process.env.PATH` (split on `path.delimiter`): on Windows it tries each directory × each extension of
  `PATHEXT` (default `.COM;.EXE;.BAT;.CMD`) and returns `viaShell: true` for `.bat`/`.cmd`; elsewhere it returns the
  first regular file with an execute bit, `viaShell: false`. `run(cmd, args)` returns `null` when `which` is `null`,
  otherwise `spawnSync(path, args, { shell: viaShell, encoding: "utf8", timeout: 15000 })` — the shell is used only for
  `.cmd`/`.bat` on Windows (Node refuses to start them without one), and the args are always constants from this file,
  never user input. **Every command in E04 runs through `run`.**
  `lib/detect.mjs` holds one table of probes so they can be corrected in one place:
  `claude`: installed `claude --version`, signed-in `claude auth status`; `cursor` (command `agent`): installed
  `agent --version`, signed-in `agent status`. `devos agents detect` prints two lines, Claude first, then Cursor, each
  exactly one of `<tool> missing` (`which` is `null`), `<tool> installed signed-out` (version probe exits 0, sign-in
  probe does not), `<tool> installed signed-in`; exit 0. Do not parse model names. Codex and Gemini are not detected.
  The sign-in probe commands are **unverified**: D6 has the owner run them on his machine; if one does not exist, the
  reviewer reissues this table — the builder never guesses another command.
- **S5 — Doctor** (`lib/doctor.mjs`, command `devos doctor`). Read the roster when the file exists. For each pool item whose `model` equals `reviewer.model`, print `devos: warning: <id> uses <model>, the same model as the reviewer`. The same check applies to `reviewer_light` when it is not null. Then, if `run("gh", ["--version"])` is `null` or exits non-zero, print `devos: gh is not installed. Install the GitHub CLI, then run: gh auth login` and exit 1. Otherwise print `devos: doctor ok` and exit 0. The warning does not by itself change the exit code. No roster file skips the warning.
- **S6 — Status.** `devos status` in a directory with no `devos/project.json` prints `devos: no project here` and exits 0. When that file exists, print `devos: project <project>` using its `project` string, then one line `devos: roster <reviewer.id>` when a roster exists, or `devos: roster none` when it does not, and exit 0.
- **S7 — Command entry.** `bin/devos.mjs` dispatches `doctor`, `status`, `profile`, and `agents`. No arguments prints exactly:

```
devos 0.1.0
devos doctor
devos status
devos profile show

devos agents detect
devos agents show

```

  and exits 2. An unknown command prints `devos: unknown command <name>` and exits 2. `--version` and `-v` are unchanged.
- **S8 — Tests** in `test/command.test.mjs` (node:test, assert/strict, spawnSync, `DEVOS_HOME` set to a temp directory that is removed afterwards). Profile set/show round-trips `github_owner` `Ada-Dev` and `cursor_accounts` `2` (stored as the number 2); `visibility` `secret` exits 1 with `devos: profile visibility must be private or public`; `default_stack` `task-runner-app` is accepted. A second import whose pool model equals the reviewer model is accepted; `devos doctor` with `PATH` set to an empty directory prints the warning line `devos: warning: cursor-grok uses claude-opus-5-5, the same model as the reviewer` and the gh line, and exits 1. ```


  Stubs: `claude.cmd`/`agent.cmd` containing `@exit /b 0` on Windows, executable `#!/bin/sh` files with `exit 0` elsewhere (mode 0o755). A unit test of `which` proves `viaShell` is `true` for a `.cmd` stub on Windows and `false` elsewhere, and that a missing command is `null`. `devos status` outside a project prints `devos: no project here`. `test/version.test.mjs` stays as it is.
