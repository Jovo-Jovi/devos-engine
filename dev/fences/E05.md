### Prompt (canonical)

Give the engine its two delivery commands. `devos install` writes the method into a project folder and records what it installed. `devos upgrade`, run by a newer engine inside an installed project, decides per file what to do from three hashes:
- what was installed (the lock);
- what is in the folder now;
- what the new release ships.

It applies only safe changes on a new branch, pushes it, and opens a pull request that lists every conflict.

Rules for the whole task:
- No payload file changes, so this is not a method change and needs no precedent row.
- Everything new is in `lib/`, `bin/` and `test/`.
- `lib/` never imports from `tools/`, which does not ship (`dev/RELEASE.md`).
- Every hash is sha256 of the LF-normalized bytes, as in the manifest. Every file the engine writes is LF.

- **S2 — `lib/engine.mjs`.**

- **S3 — The lock file**, written by `writeLock(project, version, entries)`. Its content is

  `JSON.stringify(lock, null, 2) + "\n"`. The lock lists engine files only: no templates, and not `devos.config.json`.
- **S4 — `lib/install.mjs`, `devos install [folder] --key <KEY>`.** The folder defaults to the current directory

  - **Then write:**

    - each template at `toInstalled(<path under payload/templates>)`, with `__PROJECT_KEY__` → KEY in

    - the lock (the manifest's paths and hashes, the running engine's version).
  - **Then run** `node scripts/devos/config.mjs --write` (`process.execPath`, `cwd` = the folder). A non-zero exit
    is printed and the command exits 1.
  - **Output:** `devos install <v>: <n> engine files, <t> templates, devos.config.json written` (today:
    `110 engine files, 3 templates`), then `devos: next — devos init writes the project documents (docs/PHASES.md,
    docs/GLOSSARY.md, …)`. Exit 0.

- **S5 — `lib/upgrade.mjs`, `devos upgrade [--local]`**, run in an installed project (its `cwd`) by the engine
  that is the new release.
  1. **Plan.** `planUpgrade(lock, manifest, current)` is pure. `current` maps a path to its hash or `null`. With L
     the lock hash, C the current hash and N the manifest hash (each `null` when absent), every path of
     lock ∪ manifest gets exactly one outcome:

     | L | N | C | outcome |
     |---|---|---|---|
     | null | set | null | `add` |
     | null | set | = N | `adopt` (the lock takes N) |
     | null | set | other | `conflict` "exists, not installed by devos" |
     | set | null | null | `drop` (removed from the lock) |
     | set | null | = L | `remove` (delete the file) |
     | set | null | other | `conflict` "edited locally, removed upstream" |
     | set | = L | = L | `same` |
     | set | = L | other or null | `kept` (the project's edit; nothing upstream) |
     | set | ≠ L | = L | `update` |
     | set | ≠ L | = N | `adopt` |
     | set | ≠ L | other | `conflict` "edited locally and changed upstream" |
     | set | ≠ L | null | `conflict` "deleted locally and changed upstream" |

     A `conflict` and a `kept` path keep L in the new lock. `update`, `add` and `adopt` take N. `remove` and `drop` leave the lock.
  2. **Refuse** with exit 1 and no change when any of these holds:
     - there is no lock: `devos: not installed here; run devos install`;
     - the lock's version is newer than the engine's (compare numeric semver parts):
       `devos: this project has engine <x>; this engine is <y>`;
     - `git status --porcelain` is not empty: `devos: the working tree is not clean; commit or stash first`;
     - HEAD is detached: `devos: check out a branch first`;
     - the branch `devos/upgrade-<y>` exists: `devos: branch devos/upgrade-<y> already exists`.
  3. **Nothing to apply.** When there is no `add`, `update`, `remove`, `drop` or `adopt`, and the versions are
     equal, print `devos: up to date (<y>)`, then the conflicts (if any), and exit 0 with no branch.
  4. **Apply.**
     - Record the base branch, then `git switch -c devos/upgrade-<y>`.
     - Write `add`/`update` files and delete `remove` files.
     - Write the new lock (version y).
     - If `devos/engine.defaults.json` was written and `devos/project.json` exists, run
       `node scripts/devos/config.mjs --write`.
     - `git add` exactly the written, deleted and lock paths (plus `devos.config.json` when it was regenerated).
     - Run `git commit -m "DEV_OS upgrade <x> to <y>"`.
  5. **The PR body** is written to `.git/devos-upgrade-body.md` (inside `.git`, never committed). The text is
     exactly:

     ```
     DEV_OS upgrade <x> to <y>
     ```

     followed by the sections `updated:`, `added:`, `removed:`, `conflicts:` and `kept (your edits, nothing changed upstream):`.
     - Each section is a heading line, then one `- <path>` line per path, sorted.
     - A conflict line is `- <path> — <reason>`.
     - An empty section has the single line `- none`.
     - The body ends with `Release notes:` followed by the `## <y>` section of the engine's `CHANGELOG.md` when the
       file and section exist, else `none in this release`.
  6. **Publish** unless `--local`: `git push -u origin devos/upgrade-<y>`, then `gh pr create --base <base> --head
     devos/upgrade-<y> --title "DEV_OS upgrade <x> to <y>" --body-file <abs path of the body>`. Both run through
     `run()` with `cwd` = the project and timeout 120000. A failure prints the command's stderr and exits 1;
     the branch stays.
  7. **Always switch back** to the base branch at the end, also on a publish failure.
  8. **Output:** `devos upgrade <x> to <y>: <u> updated, <a> added, <r> removed, <c> conflicts`. With conflicts, each conflict line follows. The last line is `devos: pull request opened` or `devos: branch devos/upgrade-<y> committed locally (--local)`. Exit 0.
