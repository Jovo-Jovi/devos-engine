### Prompt (canonical)

Make design a written contract and every UI fence a checked specification. A project keeps `docs/DESIGN_SYSTEM.md`
and `docs/design/UI_ACCEPTANCE.md`, written by the blueprint. Every open UI fence carries a `### Design specification`
whose states equal its `- Screens:` names and whose criteria are rows of `UI_ACCEPTANCE.md`. A new guard fails the run
otherwise. `docs/method/DESIGN_METHOD.md` states the lifecycle, the acceptance gate and the resource catalogue.

This is a method change (PR-28 spirit), so the precedent and the manual are part of it. The texts in `dev/fences/E08/`
are exact: copy them byte for byte.

### Stage 1 — the guard and the method document (proves D2–D6)

- **S1 — `payload/files/scripts/guards/design-spec.mjs`** (default export; uses `read`, `exists`, `result` from
  `./lib.mjs`, `parsePhases` from `../devos/lib.mjs` and `parseScreensLine` from `../devos/screens.mjs`).
  - **When it does not apply.** If `docs/PHASES.md` is absent, return `N/A` with the note `no docs/PHASES.md`.
  - **Which fences it checks.** For every row that is not done and has `docs/fences/<task>.md`, the fence is a UI fence when
    `parseScreensLine` finds a line, or when the part before `### Prompt` has a line `- UI: yes`.
  - **What it reports for each UI fence** (a finding names the fence path):
    - `- UI: yes` without a `- Screens:` line → `<path>: - UI: yes without a - Screens: line`;
    - each `parseScreensLine` error → `<path>: Screens line: <error>`;
    - no `### Design specification` heading → `<path>: UI fence without a ### Design specification`. The section runs to the next `### ` heading or the end of the file.
    - in the section, a missing `- States:` line or `- Criteria:` line → `<path>: no - States: line` / `<path>: no - Criteria: line`. The entries are the backticked items on that line.
    - a Screens name not in States → `<path>: <name> is on the Screens line but not in States`;
    - a state not on the line → `<path>: state <name> is not on the Screens line`;
    - criteria when `docs/design/UI_ACCEPTANCE.md` is absent → one finding, `docs/design/UI_ACCEPTANCE.md does not exist`;
    - a criterion with no line matching `^\|\s*<id>\s*\|` → `<path>: criterion <id> is not a row of docs/design/UI_ACCEPTANCE.md`.
  - **Result.** With no UI fence: `N/A`, note `no open UI fence`. Otherwise `FAIL` with findings, or `PASS` with the note `<n> UI fences checked`.
