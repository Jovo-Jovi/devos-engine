## E09 — A project links to the DEV_OS registry by request, and its steps report there without ever blocking it (method change, PR-61, engine 0.2.9)

- Phase: E · Risk: 3 · Gate: you. It is a method change: a new runner script, a new job and seven report steps in `devos-cycle`, the engine defaults, the contract, the manual, a precedent and the version.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-26.
- **From the owner's decision of 2026-10-26:** "i need only link to tower without any limitation of subscription make the link made by devos-engine as request to tower and then tower approve and add the link".
  - The link is a request from the project. The registry's owner approves it once and names the project's key.
  - Nothing ever blocks a run or a project. This replaces the GitHub App registration (TR1), the receipt check, and the 72-hour grace of D-E3.
  - The Tower side is `dev/fences/E09/TOWER-CHANGE-REQUEST.md`, for the owner to file in `devos-control-tower`.
- **Before this fence:**
  - the contract described a GitHub App registration that was never built;
  - nothing in a project sent anything to the registry;
  - the registry's event contract v1 (the Tower's `docs/contract/EVENT_CONTRACT.md`) had no sender.
- **What the copies change,** for the report:
  - **`payload/files/scripts/devos/report.mjs` (new, PR-61)** has three commands.
    - `note --step --status [--evidence]` appends one event to `.devos/journal.jsonl`: no network, no token. It validates every field and the 2 048-byte limit of contract v1, keeps `run` and `seq` in `.devos/report-state.json`, and takes the phase from `docs/PHASES.md`. `note --failed` ends a step a runner failure left open as `fail`.
    - `link` asks the registry (`POST {registry.url}/api/link`) with GitHub's OIDC token of the workflow, whose audience is `registry.url`. It keeps the answer in `.devos/link.json`: linked and its key, pending, declined, or unreachable.
    - `flush` sends each unsent event once, in order, to `/api/ingest`, with the key the registry named. The answers are handled as contract §8 says: 200 sent or duplicate; 409 a conflict, never retried; anything else kept for the next run.
    - Every command exits 0. `--dry` prints what would be sent and never a token.
    - `DEVOS_REPORTING` = off turns reporting off; an empty `registry.url` sends nothing.
  - **`devos-cycle.yml`:**
    - seven `devos-report` steps in the `cycle` job, each with `continue-on-error: true`, note the events: build started and its end, checks, review started, review and verdict, gate and merge, and a step left open by a failure;
    - a new `report` job is the only job with `id-token: write` (with `contents: read` and `actions: read`), so the agents' job never holds the OIDC permission (PR-04). It runs no agent: it downloads the run's `.devos/` artifact, then runs `link` and `flush`. It has `continue-on-error: true`, a 3-minute limit, and runs unless `DEVOS_REPORTING` is off;
    - "Act on the verdict" records the final action in `FINAL_ACTION`, and two steps get ids (`checks`, `act`).
  - **`payload/files/devos/engine.defaults.json`:** `registry.url`, empty until the release names the registry's address.
  - **`payload/contract/CONTRACT.md`, version `0-draft-3` (`lib/contract.mjs`):** Linking and Disconnecting by request. Token counts are no longer listed as reported, because E09 sends none.
  - **The rest:**
    - `AUTOMATION.md` §1, §3, §4, §7 and §8 (`report.mjs`, `DEVOS_REPORTING`, `registry`, the agents never hold the OIDC permission);
    - PR-61 in `PRECEDENTS.md`;
    - `README.md` "Your keys and data" and "Roadmap";
    - version `0.2.9`;
    - `tools/sources.mjs`: `report.mjs` added (309 files), and E09 on the changed paths.
  - **Toward developers the dashboard is never named (D-E8):** every shipped text says "the DEV_OS registry".
