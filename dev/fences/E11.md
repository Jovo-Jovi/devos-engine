### Prompt (canonical)

The project's agents live in its configuration, so the runner on GitHub can read them: `agents` in the generated
`devos.config.json`, engine defaults in `devos/engine.defaults.json`, the project's choice in `devos/project.json`
(written by `devos init` from the developer's roster in E06). The reviewer sees the builder pool in its prompt and
names a pool id in each fence header; the runner resolves that id, uses the item's model, and records a note when the
id is not in the pool. The reviewer's models come from the same section. **v1 keeps today's tools per role** —
builder through the Cursor CLI, reviewer through Claude Code — with any model each tool offers; a choice that needs the
other tool stops with a clear message (E12 adds it). Every existing flag, account loop, watchdog and limit check stays
exactly as it is.

  These reproduce today's behaviour exactly. The template `payload/templates/devos/project.json` gets no `agents` key.

- **S2 — `payload/files/scripts/devos/agents.mjs`** (dependency-free; `config()`, `emit`, `P` from `./lib.mjs`).
  - `pool()`, `byId(id)`, `defaultItem()` over `config().agents`. Validate the shape exactly as E04's `checkRoster`
    (same keys, tools `cursor|claude`, one default, policy `reviewer-picks|always-default`); a bad shape throws
    `agents: <reason>`.
  - `pick(task)`: read the fence header's `- Builder: <token> ·` (first 30 lines of `docs/fences/<task>.md`, same regex
    style as `builder-model.mjs` `readFenceChoice`). Policy `always-default` → the default item, note `""`. Otherwise
    a token equal to a pool id → that item, note `""`; any other token (including the legacy `grok-4.7`) → the default
    item, note `builder <token> is not in the pool; using <default id>`; no `Builder:` line → default, note `no Builder
    line; using <default id>`.
  - `reviewerFor(mode)`: `deep` → `agents.reviewer`; `light` → `agents.reviewer_light ?? agents.reviewer`.
  - `poolText()`: one line per item, `- <id> — <tool> · <model>[ · default][ — <note>]`.
  - CLI: `pick --task Tnn` emits `builder_id`, `builder_tool`, `builder_model`, `builder_note`; `reviewer --mode
    light|deep` emits `reviewer_tool`, `reviewer_model`; `pool` prints `poolText()`.
- **S3 — `builder-model.mjs`** (smallest change): `candidates` uses `process.env.DEVOS_BUILDER_FAMILY || b.model_family
