### Prompt (canonical)

`devos init` lets the developer choose any installed AI tool and model for every role:
- the reviewer and the light reviewer;
- the builder pool, each builder with its strengths (ui, backend, data, tests, fast and cheap, deep reasoning);
- the pick policy;
- separately, the blueprint agent on this computer.

It checks that the `gh` login can create the repository and push workflows. It takes attached documents. It runs the
blueprint on the chosen tool and model. It writes the agents into `devos/project.json`. After approval it asks for
**every key the chosen tools and deploy target need, in one sitting, as hidden input**, and then shows the plan and
asks before anything reaches GitHub. Each key goes from memory straight into `gh secret set` over standard input. It
is never in argv, a file, a log, an answer or any model's environment.

Copy the texts in `dev/fences/E15/` byte for byte. Port the Engine B modules named below, adapting their imports and
paths; never edit `dev/fences/ref/`.

### Stage 3 — onboarding: agents, preflight, attached documents, blueprint on the chosen agent (proves D1 for init cases (m)–(r), D7)

- **S10 — `lib/menu.mjs`.**
  - It exports `select`, `multiSelect`, `text`, `confirm` and `secret`.
  - They take a line reader (E06's `lineReader`, moved here) plus `process.stdout`.
  - A menu prints `  <n>) <label>` lines and `[default: <n>]`. It accepts a number, the option's value, or its label (any case). An empty line takes the default.
  - Three invalid answers print `devos: no valid answer for <title>` (exit 1). End of input prints `devos: input ended before setup finished` (exit 1).
  - `secret(title)` reads one hidden line. On a TTY, raw mode is on with no echo; a `*` is printed per character; Backspace and Ctrl-C (exit 130) are handled; raw mode is restored on every path. Off a TTY it reads a plain line.
- **S11 — `lib/init.mjs` flow.** The E06/E07 order stays, with these additions.

  2. **Agents**, right after `accept`. The menus list `<Tool label> · <model>` for every tool in `lib/data/tools.json`, installed or not, because the cycle runs on GitHub. The blueprint menu lists installed, signed-in tools only.

     2. `Light reviewer — risk 1–2 reviews` (first option `Same as the reviewer` → `null`);
     3. `Builder pool — numbers separated by commas` (multi);
     4. for each builder, `Strengths of <id>`, a multi over `builderStrengths` (empty allowed) → its `note` as `strengths: ui, backend` (or `default builder`);
