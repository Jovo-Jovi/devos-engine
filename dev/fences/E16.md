### Stage 2 — long runs (proves D1 for (e)–(g))

- **S3 — `lib/progress.mjs`.** It exports `heartbeat({ label, folder, everyMs, now })`, which returns `{ start, stop }`. Every `everyMs` (default 60000, or `Number(process.env.DEVOS_HEARTBEAT_MS)`) it prints:
  `devos: <label> · <m> min · <n> files under docs/`
- **S4 — The blueprint runs asynchronously.**
  - `runBlueprint` calls `spawnTool(command, args, { cwd, input })` from `lib/spawn.mjs` instead of `run()`. Stdout and stderr are collected as now. On Windows, `.cmd` handling is `spawn.mjs`'s.
  - While the round runs, the S3 heartbeat prints with the label `blueprint running on <tool> · <model>`.
  - A first Ctrl-C (SIGINT) during a round:
    - calls `killPidTree(child.pid)`;
    - prints `devos: stopped — the folder keeps what was written; run devos continue <folder>`;
    - exits 130.

    A second Ctrl-C exits 130 at once. The handler is removed when the round ends.
  - A round over 3600000 ms is killed the same way and reported as `devos: <command> ran over an hour and was stopped` before E07's failure lines.

### Stage 3 — `devos continue` and adopting a repository (proves D1 for (h)–(m), D5)

- **S5 — `lib/continue.mjs`, `devos continue [folder]`.** The folder defaults to the current one. The command first prints a checklist; each line is `✓` or `·`, then the step, then `(devos)` or `(you)`:
  1. `answers` — `devos/answers.json` exists (devos);
  2. `engine files` — `devos/engine.lock.json` exists (devos);
  3. `blueprint approved` — `.claude/settings.json` exists (you approve);
  4. `local commit` — `git rev-parse HEAD` succeeds (devos);
  5. `repository` — `git remote get-url origin` succeeds and `gh repo view <slug> --json name` exits 0 (devos);
  6. `keys` — `gh secret list` holds every non-optional `neededKeys` name (you type them);
  7. `first cycle` — `gh run list --repo <slug> --workflow devos-cycle.yml --limit 1 --json databaseId` returns a run (devos).

  Steps 5–7 are checked only when step 4 holds; otherwise they show `·`. Then it acts on the first `·`:
  - 1–2: print `devos: start with devos init in an empty folder` and exit 1;
  - 3: run E07 a2's blueprint resume (`--continue` path);
  - 4–7: run `finishSetup`;
  - all `✓`: print `devos: everything is done — the cycle runs on GitHub; merge its pull requests at the gates` and exit 0, dispatching nothing.

  `devos init --continue <folder>` becomes an alias of `devos continue <folder>`. Add the usage line `devos continue [folder]`.
- **S6 — `finishSetup` on a repository that exists.** When `origin` exists and `gh repo view` succeeds:
  - skip `repo create`;
  - read `gh secret list` first and ask, in the keys step, only the needed names it lacks;
  - the plan line says `Keys to upload:` for those only.
- **S7 — Adopt, never overwrite.** When `gh repo create` fails, run `gh repo view <slug> --json name,isEmpty,url`:
  - **`isEmpty` is true:** add or re-point `origin` to `<url>.git` (the `url` from `gh repo view <slug> --json name,isEmpty,url`) and push `main` normally. Print `devos: adopted the existing empty repository <slug>`.
  - **It exists and is not empty:** stop with `devos: <slug> already exists and has commits; delete it or change "name" in devos/answers.json, then run devos continue <folder>`. No push.
  - **The view fails too:** keep E07's `setup stopped at repository` line.

  A rejected push never retries with force, rebase or merge. It stops with `devos: GitHub refused the push to <slug> (it has commits this folder does not); nothing was overwritten`.
- **S8 — Tests** in `test/continue.test.mjs` and new cases in `test/init.test.mjs`. Extend the stubs inside `test/init.test.mjs` (the `ghStub` and `claudeStub` strings; export or copy them for `continue.test.mjs`). `test/fixtures/agents/gh.mjs` is the doctor's fake; touch it only for (c).

  - S7 points `origin` at `<url>.git` from that view (on GitHub, `https://github.com/<slug>.git`), so the test pushes to the local bare repository and never to the network.
  - `claudeStub` gains `STUB_MODE=hang` (never exits; writes its pid to `../model.pid` first) and `STUB_MODE=slow` (writes the docs after 300 ms).
  - **Cases:**
