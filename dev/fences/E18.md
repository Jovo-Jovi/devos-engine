### Prompt (canonical)

Make setup start from what the developer is building:
- the project type, a stack the method can run, and a provider for each module the type uses;
- then a short list of documents worth preparing;
- every key of the chosen modules typed once with the rest.

The blueprint plans the stack and the providers, and turns observability into concrete tasks. This is a method change, PR-46.

- **S2 — `lib/catalogue.mjs`.** It exports:
  - `loadCatalogue()`.
  - `typeById(id)`.
  - `stacksFor(typeId)`: the stacks whose `fits` include the type and `runs` is true, in file order.
  - `modulesFor(typeId)`: the modules named in the type's `defaults`, in catalogue module order, each `{ ...module, default }`.
  - `prepareFor(typeId)`: the type's `prepare` ids, resolved to document objects, in order.
  - `methodModules(modules)`: the sorted unique `method` values of the chosen providers, without `vercel`.

### Stage 3 — module keys, the blueprint and the method record (proves D1 for (i)–(l), D2–D6)

- **S8 — Keys.**
  - **Conditions.** In `lib/keys.mjs` and `lib/setup.mjs`, `holds("module:X")` is true when `methodModules(answers.modules ?? {})` includes `X`, for **secret items only**. Variables and Vercel items keep `false` for `module:` at init, because the method sets those when the module lands.
  - **`neededKeys` order**, with duplicates dropped:
    - the cycle keys, as today;
    - every applicable secret item with `blocks: "deploy"`: its first name when `any`, otherwise every name, all `optional: true`. This general rule replaces the special Vercel branch and keeps the Vercel names, their order and their optional flag;
    - `appKeys(answers.modules ?? {})`, all `optional: true`.
  - **`KEY_SOURCES` gains:**
    - `SUPABASE_PROJECT_REF`: `Supabase dashboard → your project → Project Settings → General → Project ID (the reference).`
    - `SUPABASE_DB_PASSWORD`: `The database password you set when you created the Supabase project (Project Settings → Database → Reset database password if you no longer have it).`
    - `DEVOS_BACKUP_PASSPHRASE`: `Any long passphrase you choose; the deploy encrypts database backups with it. Keep a copy in your password manager.`
    - `R2_ENDPOINT`: `Cloudflare dashboard → R2 → your bucket → Settings → S3 API (https://<account id>.r2.cloudflarestorage.com).`
    - `R2_BUCKET`: `The name of your R2 bucket (Cloudflare dashboard → R2).`
    - `R2_PUBLIC_BASE_URL`: `Cloudflare dashboard → R2 → your bucket → Settings → Public access: the public URL (r2.dev or your custom domain).`
    - `FIREBASE_DEPLOY_SERVICE_ACCOUNT`: `Firebase console → Project settings → Service accounts → Generate new private key; give the path of the downloaded JSON file.`
  - **File keys.**
    - `FIREBASE_DEPLOY_SERVICE_ACCOUNT` and `FIREBASE_SERVICE_ACCOUNT` are file keys: `neededKeys` marks them `file: true`.
    - The keys step asks `<NAME> — path to the JSON file (Enter to skip)` as a visible line, reads the file, and keeps its text when `JSON.parse` succeeds.
    - Otherwise it prints `devos: <NAME>: <path> is not a readable JSON file` and asks again, up to three times, then skips.
    - The content is never printed. It is uploaded like every other key, over standard input.
    - Export the function as `readFileKey(key, read, stdout)`.
