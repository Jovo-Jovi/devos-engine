### Prompt (canonical)

Let a browser drive `devos init` safely, without forking the flow:
- a **plan** (every answer, as JSON) feeds the same code the terminal uses;
- the run's few prompts announce themselves with machine-readable markers;
- a local server, reachable only from this computer with a per-run token, starts the run, streams its progress, relays the developer's answers and keys, and can stop it.

The terminal flow behaves exactly as today.

#### Steps

### Stage 1 — one plan, two front doors (proves D1 for (a)–(d))

- **S1 — `lib/plan.mjs`.**
  - **`buildAnswers(fields, project, blueprintAgent, attachmentNames)`** returns the answers object exactly as `initCommand` builds it today: same keys, same order, `derivedAnswers` and `CONTRACT_VERSION`. `initCommand` uses it.
  - **`validatePlan(plan, detected)`** checks a plan object of the shape `{ accepted, contract_version, agents, blueprint, project: { type, stack, modules, scope }, fields: { name, brief, users, languages, visibility }, attachments: [paths] }`.
    - It returns `{ ok: true, agents, answers, attachments }`, or `{ ok: false, errors: [...] }`. Each error is one plain sentence.
    - **The rules are the terminal's:**
      - `accepted === true`, and `contract_version === CONTRACT_VERSION`;
      - the name passes `KEY_RE` via `keyFromName`;
      - `brief` and `users` are not empty;
      - `languages` is a non-empty array (default `["en"]`), and `visibility` is `private` or `public`;
      - `type` is in the catalogue; `stack` is in `stacksFor(type)`;
      - every module is a module of the type, with a provider the stack allows: no `method` provider for a non-Node toolchain;
      - `scope` is `mvp` or `full`;
      - the reviewer, light reviewer and pool tools are `cycle: true` and pass `checkRoster`'s shape;
      - the blueprint agent's tool is detected, installed and signed in;
      - each attachment path exists and is a file.
- **S2 — Plan mode.** `devos init --plan <file> [folder]`:
  - **Checks.** It reads the JSON file and runs `doctorCommand` and `detectAgents`.
    - If `validatePlan` fails, it prints each error as `devos: plan: <error>` and exits 2.
    - The folder must be empty, as today.
  - **The run.** It goes straight to the code after `Continue with these answers?`: install, `project.json`, attachments, `answers.json`, then `runBlueprint`. That code becomes a function `startProject(folder, plan, read)`, which `initCommand` also calls.
  - **The reader.** It reads stdin with `lineReader`, and sets `read.isTTY = false` and `read.interactive = true`.
    - `setup.mjs` `interactive(read)` returns `read.interactive` when it is a boolean, and otherwise behaves as today.
    - So plan mode asks the keys as plain lines, without raw mode.
  - Add the usage line `devos init --plan <file> [folder]`.
- **S3 — Tests** in a new `test/plan.test.mjs`. Use the harness stubs.
  - **(a)** `buildAnswers` equals, key for key and in order, the `answers.json` a terminal `init(staged, flow())` writes. Ignore `attachments`, which are empty in both.
  - **(b)** `validatePlan` gives exactly one error each for:
    - a name whose key fails `KEY_RE`;
    - a GLM reviewer (GLM is `cycle: false`);
    - a `fastapi` stack with `database: "supabase"`;
    - `accepted: false`;
    - a blueprint tool that is not signed in.
  - **(c)** `devos init --plan` with a valid plan and the fake Claude, on stdin `approve`, then Enter for each key, then `no`:
    - it ends `stopped before GitHub — nothing was created`, with exit 0;
    - `answers.json` deep-equals the `answers.json` from (a).
  - **(d)** An invalid plan exits 2 and prints `devos: plan: ` lines; the folder stays empty.

### Stage 2 — prompt markers (proves D1 for (e)–(f))

- **S4 — Markers.** When `process.env.DEVOS_UI === "1"`, and only then, print one line before each prompt and at each step.
  - Each marker is `console.log` of `::devos-ask ` or `::devos-step ` followed by compact JSON.
  - **Asks:**
    - before the approval prompt: `{"kind":"approve","round":N,"files":[…docsUnder…]}`;
    - before each key prompt: `{"kind":"key","name":…,"where":…,"optional":…,"file":…,"index":i,"total":n}`;
    - before `Create it now?`: `{"kind":"create","slug":…,"visibility":…,"variables":[…],"upload":[…names…],"later":[…names…]}`.

    A marker never holds a value.
  - **Steps:** `{"step":"install"}`; `{"step":"blueprint","round":N}`; `{"step":"approved"}`; then, at the start of each setup stage, `{"step":"owner"}`, `setup`, `keys`, `commit`, `repository`, `permissions`, `variables`, `secrets`, `check`, `cycle`; and `{"step":"done","code":C}` as the last line of a plan-mode run.
  - Without `DEVOS_UI`, the output is byte for byte today's.
- **S5 — Tests**, new in `test/plan.test.mjs`:
  - **(e)** (c) rerun with `DEVOS_UI=1`:
    - stdout's marker lines, parsed, are, in order: `install`, `blueprint` (round 1), `ask approve`, `approved`, `owner`, `setup`, `keys`, then one `ask key` per needed key, `ask create`, `done` (code 0);
    - no marker line holds a typed value.
  - **(f)** A terminal `init(staged, flow())` without `DEVOS_UI` prints no `::devos-` line.

### Stage 3 — the local server (proves D1 for (g)–(n), D3)

- **S6 — `lib/ui-server.mjs`.** It exports `startUiServer({ folder, port = 0, token })` and resolves `{ url, port, token, close }`.
  - **Network.**
    - Listen on `127.0.0.1` only.
    - The token defaults to `crypto.randomBytes(24).toString("base64url")`.
    - `url` is `http://127.0.0.1:<port>/?t=<token>`.
  - **Every request is checked:**
    - `Host` must equal `127.0.0.1:<port>`, or the response is 403 `{"error":"host"}`. This blocks DNS rebinding.
    - Every request that is not a GET must carry `Origin: http://127.0.0.1:<port>`, or the response is 403 `{"error":"origin"}`.
    - Every `/api/` request must carry `X-DEVOS-Token` equal to the token, compared with `crypto.timingSafeEqual` on equal-length buffers, or the response is 401 `{"error":"token"}`.
    - A JSON body may be at most 24 MiB (eight 2-MiB attachments in base64), or the response is 413.
  - **Every response carries these headers:**
    - `Cache-Control: no-store`;
    - `X-Content-Type-Options: nosniff`;
    - `Referrer-Policy: no-referrer`;
    - `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; frame-ancestors 'none'`.

    Never send an `Access-Control-Allow-Origin` header.
  - **Routes:**
    - **`GET /`** (needs `?t=` equal to the token, otherwise 401) serves a placeholder page, `<!doctype html><title>DEV_OS</title><p>The guided setup page arrives in E22b.</p>`.
    - **`GET /api/state`** returns `{ contract, contractVersion, folder, empty, doctor: { ok }, agents: detectAgents() (no secrets), catalogue: { types, stacks, modules, documents }, defaults: <engine defaults agents>, visibility }`.
    - **`POST /api/plan`** takes the plan with `attachments: [{ name, base64 }]`:
      - at most 8 files, each at most 2 MiB decoded;
      - each name a plain file name: no `/`, `\` or `..`.

      It writes the files to a private temp folder, then runs `validatePlan`. It answers 200 `{ ok, summary: [lines], keys: [{ name, where, optional, file }] }`, or 400 `{ ok:false, errors }`. Only one plan is held.
    - **`POST /api/start`** (409 when no valid plan or a run is active):
      - writes the plan to the temp folder;
      - spawns `process.execPath bin/devos.mjs init --plan <file> <folder>` with `DEVOS_UI=1`, and pipes stdin and stdout;
      - answers 202.
    - **`GET /api/events`** is Server-Sent Events of `{"type":"log","text"}`, `{"type":"ask",…}`, `{"type":"step",…}` and `{"type":"done","code"}`. A late subscriber first receives every event so far. It needs the token header like every `/api/` route, so E22b reads it with `fetch` streaming: `EventSource` cannot send headers.
    - **`POST /api/answer`** takes `{ kind, value }` and is 409 unless the last unanswered ask has that `kind`:
      - `approve`: `value` is `"approve"`, or a change request of one line or more;
      - `key`: `value` is the key, or `""` to skip;
      - `create`: `"yes"` or `"no"`.

      The value is written to the child's stdin followed by `\n` and never kept or logged. A file key's `value` is base64 JSON: write it to a temp file and send its path. Answers 204.
    - **`POST /api/stop`** calls `killPidTree(child.pid)`, emits `{"type":"done","code":130}`, and answers 204.
  - **On close or after `done`,** delete the temp folder.
- **S7 — `devos ui [folder]`.**
  - It starts the server and prints `DEV_OS setup: <url>`.
  - Unless `--no-open` is given, it opens the URL with the platform opener (`cmd /c start ""`, `open`, `xdg-open`), with no shell string built from user data.
  - It runs until Ctrl-C.
  - Add the usage line `devos ui [folder] [--no-open]`.
- **S8 — Tests** in a new `test/ui-server.test.mjs`. Use `startUiServer` with `port: 0` and `fetch`; never open a browser.
  - **(g)** `GET /api/state` without the token gives 401, and with it 200 and `contractVersion`.
  - **(h)** The token header with `Host: evil.example` gives 403 `host`.
  - **(i)** `POST /api/plan` with the token and `Origin: http://evil.example` gives 403 `origin`.
  - **(j)** A body over 24 MiB gives 413, and an attachment named `../x` gives 400.
  - **(k)** Every response checked carries the four headers, and none has `Access-Control-Allow-Origin`.
  - **(l)** A full run with the fake Claude and the gh stub:
    - plan, then start, then the events show `ask approve`; answer `approve`;
    - each `ask key`: answer `kv-<NAME>-123`; then `ask create`: answer `yes`;
    - `done` comes with code 0;
    - the gh log shows `secret-stdin` lengths that match;
    - no event's text, and nothing the server writes to its stdout or stderr, contains any `kv-` value.
  - **(m)** With `STUB_MODE=hang`, start and then `POST /api/stop` give `done` with code 130 within 5 s, and the model pid is gone (`processGone`). Skipped on Windows, like E16's (f).
  - **(n)** `POST /api/answer` with `kind: "create"` while the ask is `approve` gives 409.
