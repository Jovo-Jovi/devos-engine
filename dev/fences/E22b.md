#### Steps

### Stage 0 — one answer, one line (proves D1 for (q), (r))

- **S1 — `/api/answer`.** After the kind check and before anything is written to the child:
  - **`approve`.** Split the value on `\r\n`, `\r` or `\n`. Trim each line, drop the empty ones, and join the rest with one space. An empty result answers 400 `{ ok:false, errors:["Type approve, or describe the changes."] }`.
  - **`key` and `create`.** A value holding `\r` or `\n` answers 400 `["An answer must be one line."]`.
  - **`create`.** A value other than `yes` or `no` answers 400 `["Answer yes or no."]`.
  - **A file key.**
    - `""` writes `\n`, which skips it.
    - Any other value must match `^[A-Za-z0-9+/]+={0,2}$` and decode to JSON, as today. Otherwise it answers 400 `["The file key is not base64 JSON."]`.
  - **Every refusal** clears the value, sends nothing to the child, and leaves the ask open.
- **S2 — Two more state answers.**
  - **`GET /api/events`.** When the run has finished (`finished` is true), write the replay and end the response.
  - **`GET /api/state`** adds three fields:
    - `tools`: `lib/data/tools.json` `tools` mapped to `{ id, label, cycle }` (`cycle` is `tool.cycle === true`), in that order;
    - `strengths`: its `builderStrengths`;
    - `run`: `"finished"` after a `done`, otherwise `"running"` while a child runs, otherwise `"idle"`.
- **Tests**, new in `test/ui-server.test.mjs`:
  - **(q)** A worker with a normal stage. The plan comes from a separate stage, with `project.modules.database = "firebase"`.
    - **At `ask approve` round 1:**
      - `"  \n "` gives 400 with `Type approve, or describe the changes.`;
      - `"split phase 2\n\ninto two"` gives 204.
    - **The next approve ask** has round 2. The worker answers `approve`.
    - **The asks seen** have rounds `[1, 2]` exactly.
    - **At the first key ask:** `"kv-a\nkv-b"` gives 400 with `An answer must be one line.`. Then every key answers `""`, the file key included, and each gives 204.
    - **At `ask create`:** `"maybe"` gives 400 with `Answer yes or no.`, then `"no"` gives 204.
    - **The end:**
      - `done` code 0, and a log line contains `nothing was created`;
      - a new `GET /api/events` replays and ends within 2 s;
      - `GET /api/state` gives `run: "finished"`.
  - **(r)** `GET /api/state` before any plan:
    - `run` is `"idle"`;
    - `tools` deep-equals the mapped `tools.json` list (6 entries);
    - `strengths` deep-equals `builderStrengths`.

The page reads `t` from its URL, keeps it in `sessionStorage` for that tab, and removes it from the address bar. Every `/api/` route keeps its header check, and the Host check still comes first.
