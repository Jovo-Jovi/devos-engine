## E22e — The blueprint runs on the tool the developer picks, and a stopped project continues from the page

- Phase: E · Risk: 2 · Gate: you. It changes how the blueprint reaches the Cursor CLI, and adds a server route that runs `devos continue`.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 3
- Fence version: v1 · 2026-10-24. Written after the E22d merge, from the owner's diagnostics.

  - the page said `devos: agent exited with 1` and nothing else;
  - "it should be users choice no forced selection": every listed tool must work, Cursor included;

#### Steps

### Stage 1 — the blueprint on Cursor (proves D1 for init (n) and (u))

- **S1 — `lib/init.mjs`.**
  - **The constants.** Add `const BLUEPRINT_INPUT = ".devos/blueprint-input.md";` and export `BLUEPRINT_POINTER`, exactly `Read the file .devos/blueprint-input.md in this folder and do exactly what it says.`
  - **`blueprintArgs("cursor", …)`** ends with `BLUEPRINT_POINTER`, after `--output-format json`. The other tools' arguments do not change.
  - **`runBlueprint`.** For `cursor`, every round writes the round's input to `<folder>/.devos/blueprint-input.md` (creating `.devos/`). This is the text that the other tools get on standard input. Nothing is written to Cursor's standard input, which is closed at once. The other tools keep standard input.
    - The file stays. `.devos/` is ignored by the project's `.gitignore`, and the call to try by hand needs it.
  - **`explainBlueprintFailure(folder, result, command, args)`.** After the `devos: <command> exited with <N>` line, when stdout and stderr are both empty after `trim()`, print two lines:
    - `devos: <command> printed nothing. To see why, run the same call by hand in <folder>:`
    - two spaces, `<command>`, then each argument separated by one space. An argument that matches `^[A-Za-z0-9_@%+=:,./-]+$` is shown as is. Any other argument is shown in double quotes, with each `"` written as `\"`.
- **S2 — `test/harness.mjs`, the `toolStub`.**
  - **Silent mode.** Right after the `if (!prompt) process.exit(0);` line: under `STUB_TOOL_MODE=silent`, exit 1 with no output.
  - **The Cursor check.** When the stub runs as `agent` (the basename of `process.argv[1]` starts with `agent`), it checks the last argument. If that argument starts with `-`, or the one before it is `--model` or `--output-format`, the stub fails. It writes `Error: No prompt provided for print mode\nError: command failed unexpectedly.\n` to stderr and exits 1. This is what the real CLI printed for the owner.
  - **The log.** Each logged line gains `input`: the text of `<cwd>/.devos/blueprint-input.md`, or `""`.
- **S3 — `test/init.test.mjs`.**
  - **Test (n)** replaces its `stdin` assertion with three:
    - the last argument equals `BLUEPRINT_POINTER`'s text;
    - `stdin` is `""`;
    - `input` starts with `# Blueprint`.
  - **New (u)**, `init.test.mjs (u) an agent that fails without a word gets the call to try by hand`. It runs `stage({ tools: ["agent"] })` with `flow({ blueprint: "Cursor CLI · grok-4.7" })` and `STUB_TOOL_MODE=silent`. The status is 1, and the output contains:
    - `devos: agent exited with 1`;
    - `devos: agent printed nothing. To see why, run the same call by hand in`;
    - `  agent --trust --force -p --model grok-4.7 --output-format json "Read the file .devos/blueprint-input.md in this folder and do exactly what it says."`

### Stage 2 — continue from the page (proves D1 for ui-server (t) and (u))

- **S4 — `lib/continue.mjs`.**
  - **`startedProject(folder)`.** Export it. It returns `{ started, approved }` from local files only:
    - `started` is true when `devos/answers.json` and `devos/engine.lock.json` both exist;
    - `approved` is `started` and `.claude/settings.json` exists.
  - **The marker.** `continueCommand` runs the existing body (move it to `continueSteps`). Under `DEVOS_UI=1` it then writes `"\n"` and prints `::devos-step {"step":"done","code":<code>}`, and returns the code.
  - **The reader.** Under `DEVOS_UI=1`, the line reader gets `isTTY = false` and `interactive = true`, as in plan mode, so the page's answers (file keys as `base64:`) are read the same way.
- **S5 — `lib/ui-server.mjs`.**
  - **Standard error.** The run's standard error is read as text, line by line. Each non-empty line, without a trailing `\r`, is emitted as `{ type: "log", text }`, never as a marker. What is left is emitted on close.
  - **`runDevos(args)`.** One function spawns `bin/devos.mjs` with `args`, as `/api/start` does today, and handles `close` as today. `/api/start` calls `runDevos(["init", "--plan", planFile, root])`.
  - **`POST /api/continue`.** The route takes the same token, Host and Origin checks as every other route.
    - A running child answers 409 `{"error":"state"}`.
    - The body may be empty. If it is not:
      - it must be JSON, else 400 `["The request is not JSON."]`;
      - it must be a plain object, else 400 `["The request is not a JSON object."]`.
    - **The folder.** In choose mode, a non-empty `folder` string is checked by two of E22d's rules, with their sentences: `path.isAbsolute`, then not the engine folder or inside it. If it passes, it becomes the target. Otherwise the target is the current folder.
    - **No started project.** When there is no target, or `startedProject(target).started` is false, the answer is 400 `["That folder holds no started DEV_OS project."]`.
    - **Otherwise:**
      - the folder becomes the target;
      - the events are cleared, `unanswered` and the held plan are cleared;
      - `runDevos(["continue", folder])` runs, and the answer is 202.
  - **`GET /api/state`** adds two fields:
    - `started`: `startedProject(folder).started`, or `false` while there is no folder;
    - `projects`: in choose mode, the started projects among the folders directly under `suggest`, otherwise `[]`. Each is `{ name, folder, approved }`, newest `devos/answers.json` first, at most 20.
- **S6 — Tests in `test/ui-server.test.mjs`**, workers like (s).
  - **(t), `ui-server.test.mjs (t) a failed run continues from the page`.**
    - **Setup.** The plan comes from a separate stage. The run's stage uses `stage({ mode: "fail" })`.
    - **Before any run,** `POST /api/continue` gives 400 with `That folder holds no started DEV_OS project.`
    - **The failed run.** After plan and start, the run ends with a non-zero `done`, and a `log` event contains `printed nothing`. `/api/state` then gives `started: true`.
    - **The continued run.** With `STUB_MODE=good`, `POST /api/continue` gives 202. The new events reach `ask approve`. Stop it. The first `done` is 130, which proves that the old events were not replayed.
  - **(u), `ui-server.test.mjs (u) the page lists started projects and refuses other folders`.**
    - **Setup.** Stage the stubs. Then set `HOME` and `USERPROFILE` to a new temp folder. Under `devos-projects` in it, create `old-app` with `devos/answers.json` and `devos/engine.lock.json`, and an empty `loose-folder`. Start the server with `folder: null`.
    - **The list.** `projects` equals `[{ name: "old-app", folder: <its path>, approved: false }]`.
    - **The refusals.** `POST /api/continue` with each of these `folder` values gives 400 with its sentence:
      - `relative/app`;
      - `<engine>/inside-app`;
      - `loose-folder`'s full path.
