## E22g — A quiet round stops itself, Continue checks a written blueprint, and the page keeps your choices

- Phase: E · Risk: 3 · Gate: you. It changes how a blueprint round ends and how `devos continue` resumes an unapproved blueprint. It also adds a file of choices in `~/.devos/` and changes the page. Nothing in `payload/` changes.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-24.
- **The owner's run of 2026-10-24, 8:34 PM, Windows, Cursor `grok-4.7-xhigh-fast`:**
  - **The page forgot his choices.** He tapped Continue on a project, saw the default choices, and started over.
  - **The round looked stuck.** By minute 19 the documents and fence T01 were written. At minute 21 the agent started a helper ("Audit fence T01"). After that came no event, no file change and almost no CPU. The round would only have ended at the one-hour limit, as an error.
- **The causes,** found on the tree:
  - the page keeps its draft in `sessionStorage`, which a new tab, and so every `devos ui` start, does not have; E22b keeps `localStorage` out of the page;
  - while a project continues, the page drew its own draft, not the project's answers;
  - `devos continue` reran the whole blueprint even when the documents were written;
  - a round ended only on the agent's result, the process exit or the hour.
- **What the copies change,** for the report:
  - **A quiet round stops itself** (`lib/init.mjs`). The limit is 15 minutes, or `DEVOS_IDLE_LIMIT_MS`. It means no output from the agent and no file changed in the project (`.git`, `node_modules` and `.devos` left out).
    - The engine prints `devos: <command> made no progress for <span> (last step: …); the round was stopped`.
    - A round stopped this way or by the hour, whose `docs/PHASES.md` exists, goes to the checks. If they pass, it prints `devos: the documents it wrote pass the checks; review them` and asks for the review. Otherwise a repair round follows.
  - **The session is kept.** Each round's agent session goes to `.devos/blueprint-session.json`. `blueprintArgs` gains `follow`, so a repair can carry on that session (`--resume <id>` for Cursor, `--continue` for Claude Code).
  - **`resumeBlueprint` checks a written blueprint** before it drafts anything:
    - passing documents go straight to the review (`devos: the blueprint is written and passes its checks; review it`);
    - failing ones get one repair round (`devos: the written blueprint fails these checks:`);
    - with no `docs/PHASES.md`, the whole blueprint runs as before.
  - **The server** (`lib/ui-server.mjs`):
    - an accepted plan's choices go to `~/.devos/choices.json` (`rememberChoices`): the agents, the blueprint agent, the type, stack, modules and scope, the languages, the visibility, and the folder that holds the projects. They never include a key or the project's name, brief or users;
    - `/api/state` returns them as `choices`;
    - `/api/project` returns the project's saved `choices` (`savedChoices`).
  - **The page** (`lib/ui/app.js`):
    - a new start begins from the remembered choices (`withRemembered`), keeping only what this computer and the catalogue still offer;
    - a continued project shows its own choices (`withChoices`).
  - **The README** gains the quiet-round stop, Continue on a written blueprint, and the kept choices.
