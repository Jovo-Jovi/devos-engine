- Phase: E · Risk: 3 · Gate: you. It is a method change: `verdict.mjs`, `limits.mjs`, `limit-check.mjs`, `render-prompt.mjs`, the cycle and intake workflows, the builder prompt, the manual and a precedent. The version changes too.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1

- **The owner's run of 2026-10-24** (`Jovo-Jovi/hello-cli` PR #3, engine 0.2.1, Cursor `grok-4.7-xhigh-fast` for every role):
  - **What happened.** Cursor reviewed T01, wrote `VERDICT: PASS`, wrote fence T02 and exited 0. The log reads `reviewer: cursor grok-4.7-xhigh-fast (deep review)` and `reviewer exit code: 0 (cursor account 1)`.
  - **What the verdict said:** `WAIT → quota_wait`, "could not read .devos/reviewer.json: Unexpected non-whitespace character after JSON at position 221", "the reviewer stopped on a Claude usage or rate limit", "Claude is out of plan usage". A re-review was scheduled.
- **The causes,** found on the tree:
  - `verdict.mjs` read the reviewer's output with `JSON.parse`. Claude Code writes one object, but Cursor writes `stream-json`, one event per line.
  - `looksLikeLimit` then searched the whole stream. That stream holds every file the reviewer read, and the method's own scripts are full of "usage limit", "quota" and "429". So the finished review counted as a limit, and the PASS in its review file was never read.
  - The limit and wait messages are hard-coded to "Claude". The run stats read `0k tokens` for a Cursor run.
  - The builder prompt names Cursor whatever the builder is.
- **What the copies change,** for the report:
  - **`limits.mjs`:**
    - `looksLikeLimit` reads only the last `LIMIT_TAIL` (4000) characters of each text;
    - `finishedRun(json)` is true for a result with no error flag and no `error…` subtype;
    - `agentStats(rel, tool)` counts a non-Claude run's tokens with `usage.mjs` `parseUsage`.
  - **The cycle's reviewer step** writes `.devos/reviewer-run.env` (`code`, `used`, `accounts`, `tool`) for every tool. It reads permission denials from the last JSON object, and it passes `DEVOS_BUILDER_TOOL` to the builder and reviewer steps.
  - **`verdict.mjs`:**
    - It reads the last JSON object of any tool's output (`parseJsonLoose`), and `.devos/reviewer-run.env`.
    - A run that exited 0 with a finished result, or gave its structured answer, is never limited. A tool with no structured answer has its verdict read from its complete review file (PR-21), with a note that names the tool.
    - The limit and wait messages name the reviewer's tool.
  - **`limit-check.mjs`** says it reads only the end of the output.
  - **`render-prompt.mjs` `BUILDER_TOOL`** gives `builder.md` the builder's real tool ("Cursor", "Claude Code", "Codex", "Gemini") and the rules file of each.
  - **The intake act step** reads only the end of a planning run for a limit.
  - **PR-54**, the manual (`verdict.mjs`, `limits.mjs`), `tools/sources.mjs` labels, version `0.2.2`, and `test/reviewer-output.test.mjs` (new).
