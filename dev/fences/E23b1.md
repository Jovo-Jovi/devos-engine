## E23b1 — The skills catalogue: every task reads the skills of its layers, on any stack (method change, PR-55, engine 0.2.3)

- Phase: E · Risk: 3 · Gate: you. It is a method change: the skills manifest, a generated index, a new runner script, the skills guard, the prompt renderer, five prompts, the compose-ui skill, the design method, the manual and a precedent. The version changes too.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-25.
- **E23b, split into phases** (owner brief, 2026-10-24: a stack-agnostic skills ecosystem — catalogue, a model-readable discovery reference with task and phase mappings, layered selection, licence and trust review, production-readiness gates):
  - **E23b1 (this fence): the frame.** Layers, stacks, the trust review and file-by-file reads in the catalogue; the discovery reference; selection by layer, role and stack in the prompts. The design skills E14 shipped move into it unchanged.
  - **E23b2:** vetted skills for the backend, api, database and security layers, for every stack.
  - **E23b3:** design and motion references: a library by product type (Lenis, GSAP, React Bits and others), plus the references the developer gives at onboarding. Each project gets its own direction, and a later redesign is a change request.
  - **E23b4:** production-readiness gates per layer, for a project whose scope is the full product.
- **Before this fence,** the design skills reached the agents through one hand-written table in `devos/skills/README.md`. Each prompt told its role to find its rows there. Nothing knew a task's layers or the project's stack, and no other layer had a place.
- **What the copies change,** for the report:
  - **`devos/skills/manifest.json` version 2** gains the layer vocabulary (`layers`: design, motion, frontend, accessibility, backend, api, database, security, testing, ops).
    - Every entry gets its `layers`.
    - Every vendored entry gets `stacks` (`any`), a `trust` review (`runs_code: false`, `fetches: false`, `reviewed`, `notes`) and `reads`: per file, the roles, the layers and when.
    - The 7 shipped skills keep their files and hashes. Their `reads` are the rows of the old README table.
  - **`devos/skills/INDEX.md` (new, generated)** is the discovery reference. It lists the layers with their file counts, a table per layer (file, blueprint, builder, reviewer, when, stacks), the shipped skills (source, licence, trust, layers), and the skills evaluated and not shipped.
  - **`scripts/devos/skills.mjs` (new):**
    - `layers --task Tnn` reads the fence's `- Layers:` line. A UI fence without it has design, frontend, accessibility and motion; a method fix has none.
    - `select --task Tnn --role R` lists the files of those layers for the role and the project's stack.
    - `list` shows every skill, `local.json` included.
    - `index [--check]` writes or checks `INDEX.md`.
  - **`guard:skills`** checks each entry's layers, a vendored entry's stacks, trust review and reads, and that `INDEX.md` is current.
  - **`render-prompt.mjs`** fills `{{SKILLS_BLOCK}}`: the builder's and the reviewer's list of skill files for the task. `builder.md` and `reviewer.md` show it.
  - **`blueprint.md`, `intake.md`, `reviewer.md` and `revise.md`** write `- Layers:` on every fence. The blueprint chooses with the Blueprint column of `INDEX.md`.
  - **`devos/skills/README.md`** says how a task gets its skills, how to read them, the trust review, and how to add one. **`devos-compose-ui`** and `DESIGN_METHOD.md` §2 and §7 point to the list in the prompt.
  - **PR-55**, the manual (`skills.mjs`, `guard:skills`, `devos/skills/`, the `- Layers:` line), `tools/sources.mjs` labels, version `0.2.3`, and `test/skills.test.mjs` (a)–(i).
