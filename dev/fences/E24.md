## E24 — The usage record: every agent run's tokens in the project, totals by model, stage and task, and engine 0.2.0 (method change, PR-52)

- Phase: E · Risk: 3 · Gate: you. It is a method change: a new runner script, changes to four workflows, the watchdog, `run-agent.sh`, `sync-main.sh`, the builder's surface, a project template, the blueprint's agent calls, and a precedent.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-24.
- **The owner's ask, 2026-10-24:** "when use any model in any stage the used tokens of whole task to be recorded in a file … for user to calculate whole project cost across selected models".
- **The design.**
  - Every run of an agent CLI adds one line to `.devos/usage/pending.jsonl` (`scripts/devos/usage.mjs record`). The line holds:
    - the stage, task and attempt;
    - the tool and model;
    - the input, output, cache-read and cache-write tokens, as the tool reported them;
    - the tool's own cost, seconds and exit code.
  - Where the lines come from:
    - **the builder:** `agent-watchdog.sh` records every run under `DEVOS_USAGE_STAGE`, so restarts, other accounts and the pool's next agent count;
    - **the reviewer:** each Cursor and Claude Code call is recorded in the workflow, and each Codex and Gemini call in `run-agent.sh`;
    - **planning:** each intake and revise call;
    - **the blueprint:** `devos init` records each round through the project's own script.
  - The runner moves the lines into `docs/usage/<task>.jsonl` in its own commits (merged by union) and rebuilds `docs/USAGE.md`, the totals:
    - the cost is the tool's own figure (Claude Code), or the tokens priced by `devos/prices.json`, a new project template the developer fills in;
    - DEV_OS never looks prices up;
    - a conflict in `docs/USAGE.md` alone is resolved by counting it again.
  - The gate doctor and the supervisor commit nothing, so their usage goes on their run summary.
  - The builder may not edit the record.
- **What each tool reports** (each parser is in `usage.mjs`):
  - Claude Code: `usage`, `modelUsage` and `total_cost_usd` on its result;
  - Cursor CLI 2026.07 and later: `usage.inputTokens`, `outputTokens`, `cacheReadTokens` and `cacheWriteTokens` on its result, no cost. Older builds have top-level `inputTokens` and `outputTokens`;
  - Codex: `turn.completed.usage`, where `cached_input_tokens` is inside `input_tokens`;
  - Gemini: `stats.models.*.tokens`, where `cached` is inside `prompt` and `thoughts` are billed as output.

  For the blueprint, Codex now runs with `--json` and Gemini with `--output-format json`; `agentText` prints their closing message.
- **The version.** The engine goes to `0.2.0`, so `devos upgrade` gives each project a new branch, `devos/upgrade-0.2.0`. From this task on, every payload change raises the version.
