- **What the copies change,** for the report:
  - **`lib/ui-server.mjs`:**
    - `GET /api/models[?folder=]` answers `{ ok, slug, roles }`. Each role has `role`, `name`, `tool`, `id`,
      `configured`, `inherited`, `override` and `effective`. A lookup that fails is `{ ok: false, errors }`, with
      status 200.
    - `POST /api/models` takes `{ folder?, role, model }` and answers `{ ok: true, message }`. `model` is a model id to
      set the variable, or `null` to remove it. A refused change is status 400 with `{ ok: false, errors }`, and
      calls gh not at all.
    - Folders follow `GET /api/project`'s rules: a full path, outside the engine, a started project; without a folder,
      the page's own.
    - Both routes answer 409 while a run is going.
    - The token, Host and Origin checks apply as to every `/api/` route.
  - **`lib/models.mjs`:** `changeMessage(result)` is the one sentence for a set or a reset. `devos models` prints it
    too, so its output does not change.
  - **`lib/ui/app.js` and `app.css`:**
    - every started project's row gets **Models** next to **Continue**, and a started folder gets **Models of this
      project** under its checks;
    - the panel lists the three roles, each with:
      - its tool and the model in use, and whether a variable or the configuration sets it;
      - the tool's model list (the one the blueprint picker uses), with **Use this model**;
      - **Back to the configured model** when a variable is set.

    It uses the page's existing tokens and components only.
  - **`README.md`** ("After setup") and **`CHANGELOG.md`** (1.1.0): the page's Models button.
  - **`test/ui-models.test.mjs`** (new), (a)–(c):
