- **What the copies change,** for the report:
  - **`scripts/devos/agents.mjs`:**
    - an agent (`reviewer`, `reviewer_light`, each `pool` item) may have `fallback_models`: up to 4 model ids of its
      own tool, none twice;
    - `fallbacks(item)` gives them in order, without the agent's own model, so a model variable (PR-63) that names
      one is not tried twice;
    - `pick` emits `builder_fallbacks`, and `reviewer` emits `reviewer_fallbacks` (space-separated); `pool` shows
      "(then …)".
  - **`scripts/devos/accounts.sh`:**
    - `devos_slots <tool> <model>…` gives `<model>@<account>` in order: each model on every account
      (`devos_accounts`, so `DEVOS_ACCOUNT_SWITCH=off` keeps one), then the next model;
    - `devos_limit_file` keeps PR-29's `.devos/limits/<tool>-<n>.txt` for the first model, and `<tool>-<n>-m<k>.txt`
      for model k;
    - `devos_unavailable` (through `limit-check.mjs --unavailable`, `limits.mjs` `modelUnavailable`) tells a model the
      account cannot use from a limit. It reads only the CLI's own error: the error output and a final result or
      error object, never a tool's output in the transcript, and never a watchdog stop (124, 125, 126);
    - `devos_settle`: when the last slot could not use its model but an earlier one was limited, the run ends
      limited. That limit's text and a last line naming it join the error file, so the run parks instead of failing.
  - **The runs.** Each one loops over the slots: a limit moves on, a model the account cannot use is skipped at once,
    and the run ends on the first that runs. The runs are:
    - `devos-cycle.yml`: the builder (Claude Code, Cursor; Codex and Gemini through `run-agent.sh`) and the
      reviewer (the same four);
    - `run-agent.sh`: it takes the models after the prompt file;
    - `plan-agent.sh`: intake, method fixes and revisions, with the reviewer's models.

    The builder step outputs the `model` it used. The commit message, the evidence and the reviewer's
    `DEVOS_BUILDER_MODEL` name that model. `reviewer-run.env` and `<role>-run.env` add `model=`.
  - **`builder-status.mjs`:** `--tool` (the cycle passes the builder's tool) chooses whose limit files give the
    earliest reset. **`review-mode.mjs`:** its header says the model it gives is the reviewer's first.
  - **The manual and the precedent.**

    - `docs/method/PRECEDENTS.md`: PR-64, and "Live maximum: PR-64". PR-53's text stays; PR-64 replaces its "no
      fallback model". The gate doctor's and the supervisor's AI second opinion keep the reviewer's first model.
