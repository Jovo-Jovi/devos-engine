## E28 — The Control Tower link without a task to run: a devos-cycle link run asks, devos-advance starts it after the link answer is merged, and the page asks now (method change, engine 1.2.1, PR-65)

- Phase: E · Risk: 3 · Gate: you. It is a method change: the condition of the cycle's `report` job (the only job with
  `id-token: write`), a link run in `next-task.mjs`, a new `devos-advance` job, the manual and a precedent. A page route
  starts a workflow on the project's GitHub repository through gh.
- Builder: grok-4.7 · Effort: medium · Fast: no
- Stages: 1

- **The owner's report of 2026-10-27:** "done the upgrade; i tried to connect to tower but nothing happen". On
  hello-cli, the link pull request (#7) is merged, `DEVOS_REPORTING` is on, and T01 and T02 are PASS. The owner's
  answer on the approach: "you search best approach".
- **The cause.**
  - Only the `report` job of a `devos-cycle` run asks the registry for the link (PR-61), and it runs only when the
    `cycle` job runs.
  - A run with every task PASS stops at `resolve`, and nothing starts a run after the link answer is merged. So a
    finished project never asks.
  - The page also said "Linked" when only the variable was on.
- **The approach, and why.**
  - **The contract stays as it is.** The request stays in the cycle's `report` job, so the accepted contract v1 stays
    true word for word: "the project's cycle asks", and "the cycle's `report` job … alone receives GitHub's
    `id-token: write` permission". A separate link workflow would change those sentences: contract v2, and every
    linked project accepting it again.
  - **No task is ever started.** A link run is `devos-cycle` with `task=link`, which `next-task.mjs` resolves as done
    before it reads `docs/PHASES.md`. Nothing dispatches one while a `devos-cycle` run is queued or going, so no
    pending run of the concurrency group is cancelled.
  - A separate security review of the first design found no blocker. Its should-fix items are in this package: the
    link marker, a failed run listing never counting as "no run", the `link` job's own permissions, and the refusal
    while paused.
