- **The approach.**
  - **What is sent.** The plan goes as step events with exactly the event contract v1's fields:
    - a finished task is `verdict pass`, dated by the commit that added its review, with that review as evidence;
    - a task still to do is `intake pass` (planned), dated by the plan's commit.

    Task names and file contents are never sent. git gives only paths and dates.
  - **When.** Only in a link run (PR-65), and only once the Tower has approved the link: nothing else in the project
    knows when that happened.
  - **One run per plan.** The run is `import-<the plan's commit>`, with the task's row as the sequence number, so a
    second link run on the same plan sends only duplicates.
  - **Paced.** At most 50 stored in any 61 seconds, under the Tower's 60 a minute, for at most 5 minutes.
    - The OIDC token, which lives 5 minutes, is asked for again every 4 minutes and once after a 401.
    - The next link run sends the rest.
  - **Contract version 2.** Version 1 says "each step of the cycle sends one event", and this plan includes work from
    before the link. So:
    - version 2 adds one sentence saying so, before it is accepted;
    - the plan goes only to a project that accepted version 2 or later;
    - a project linked under version 1 sees "Accept the contract's version 2" on its page, and **Accept by pull
      request** opens the same link pull request. Its merge starts a link run (PR-65).
