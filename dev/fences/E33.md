## E33 — Adopting an existing project, step 1: `devos adopt --check` surveys a project you already have and changes nothing (D-E13, engine 1.4.0)

- Phase: E · Risk: 2 · Gate: you. A new command in `bin/` and `lib/`, read-only. No payload file changes, apart from
  the manifest's version.
- Builder: grok-4.7 · Effort: low · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-31.
- **The owner's request of 2026-10-31:** add DEV_OS to a project that already exists on the developer's computer
  and on their own GitHub repository, in development or in production. Analyse it first, tell the developer what
  stage it is in, ask them to confirm, then continue its development with DEV_OS. The owner's answers the same day
  became D-E13:
  - the engine's files land on a branch with a pull request;
  - the existing code gets a baseline;
  - projects that run an older hand-copied DEV_OS are adopted too, the Control Tower first.
- **The series** is E33 to E39 in `dev/LEDGER.md`: survey, brief, baseline, install by pull request, production,
  older copies, then the guided page. This task is the survey only.
- **Before this fence (`main` @ 442ce2c, 1.3.2):** `devos init` adopts only an empty repository ("already exists
  and has commits"), and nothing reads an existing project.
- **What the copies change,** for the report:
  - **`lib/adopt.mjs` (new):** `surveyProject(folder, { exec })` returns the survey (`schema` `devos-survey/1`):
    - the repository: origin, branch, clean tree, commits, first and last dates, contributor count, tags. From `gh`:
      permission, visibility, default branch, open pull requests, and DEV_OS's four module switches among its
      variables;
    - the stack: toolchain, package manager, TypeScript, frameworks, the catalogue stack it matches, scripts, tests
      and runners;
    - the services by module (database, storage, auth, payments, email, jobs, search, product AI, observability);
    - the workflows and the deploys, from deploy files, from what non-DEV_OS workflows run, and from `DEVOS_VERCEL`;
    - an older copy of DEV_OS (`none`, `copy` with its precedents' live maximum, or `engine`);
    - the overlaps: engine files that exist (same or different) and the project documents DEV_OS writes;
    - the environment names from example files only, the languages, the size;
    - the stage (`prototype`, `in-development`, `production`, with its reasons), the blockers and the notes.

    `surveyLines(survey)` gives the printed lines. `adoptCommand(args)` is `devos adopt --check [folder] [--json]`:
    exit 0 when ready, 1 when something stops it, 2 for the usage.
  - **Read-only.** It writes nothing and runs no git command that changes the repository. It reads tracked files
    only, and of environment files only `.env.example`, `.env.sample`, `.env.template` and `.env.dist`, keeping
    their variable names.
  - **`bin/devos.mjs`:** the usage line `devos adopt --check [folder] [--json]` after `devos continue [folder]`, and
    the `adopt` command.
  - **Version 1.4.0** (a new command):
    - `package.json`, `test/version.test.mjs` and `test/install.test.mjs`;
    - `test/upgrade.test.mjs`, whose fake next version is now 1.4.1;
    - the README's version line, its upgrade example and a Commands row;
    - `CHANGELOG.md`: `## 1.4.0 — Unreleased`, "Adopting an existing project (D-E13)".
  - **Tests.** `test/adopt.test.mjs` (new), (a)–(f), on real git repositories built in the test, with `gh` faked:
    - (a) a Next.js project that deploys and has a tag is production; its stack, modules, workflows and overlaps;
    - (b) only an example environment file is read, and no value appears in the survey or its lines;
    - (c) each blocker: uncommitted changes, an origin not on GitHub, write access only, `gh` unable to read, the
      engine already installed. HEAD and the tree are unchanged;
    - (d) an older copy is recognised with its precedents, and its own workflows are not read as deploys;
    - (e) a small Python API is a prototype;
    - (f) the command prints the survey, `--json` the same survey, with nothing changed; the usage, and a folder
      that is not a repository.
- Rehearsed against `main` @ 442ce2c (`Release v1.3.2`). Clean worktree, S1–S2 applied, Linux, Node v22: every line
  of *Done when*. It also ran on two real clones: an older copy (`older copy (precedents up to PR-39)`) and an
