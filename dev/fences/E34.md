  - **`devos adopt [folder] [--agent <tool>[:<model>]]`** (`lib/adopt.mjs`, `adoptBrief`):
    1. the survey, as `--check` prints it; a project that is not ready stops there (exit 1), before any tool runs;
    2. the agent: `--agent`, else the default reviewer when its tool is signed in, else the first signed-in tool

    3. the staging folder `~/.devos/adopt/<owner>__<repo>/` (`DEVOS_HOME`), started fresh. It holds:
       - `workspace/`, a copy of the tracked files (the tree is clean, so its HEAD), with no `.git`;
       - `survey.json`, without the project's folder path;
       - `adopt-input.md`, the prompt `lib/data/adopt-prompt.md` plus the catalogue's type and stack ids;
    4. rounds of the tool with `cwd` = the staging folder (up to 5, the same session after the first):
       - Claude Code may only `Read,Glob,Grep,Write,Edit`, and `Bash,WebFetch,WebSearch` are refused;
       - Cursor gets a `.cursor/cli.json` that allows `Write(brief/**)` only;
       - Codex runs `--sandbox workspace-write`, and Gemini `--approval-mode auto_edit`;
    5. after every round, the project's HEAD and `git status --porcelain --untracked-files=all` must be unchanged.
       Otherwise it stops (exit 1) and keeps nothing;
    6. `checkBrief`: `brief/brief.md` has the nine headings in order, and `brief/brief.json` matches
       `devos-brief/1` (name, key, stage, catalogue type and stack, personal data, at most 10 questions). A failed
       check is sent back as a repair round;
    7. the brief is shown. `yes` writes `brief/confirmed.json` (`devos-brief-confirmed/1`, with the repository and
       HEAD). Other text is a change round. An empty line stops (exit 0), and ended input stops with exit 1.
  - **`lib/init.mjs`:** `export` on six existing names it already defines (`BLUEPRINT_TOOLS`, `toolCommand`,
    `STREAMING`, `runToolRound`, `engineDefaults`, `modelOptions`). Nothing else changes.
  - **`lib/data/adopt-prompt.md` (new):** what the tool reads, writes and must never do. It writes two files in
    `brief/` only. It never edits `workspace/`, runs no command, uses no network, and never copies a secret or a
    real person's details.
  - **`bin/devos.mjs`:** the usage line `devos adopt [folder] [--agent <tool>[:<model>]]`, and the command awaited.
  - **`test/harness.mjs`:** the fake Claude Code writes a brief when its folder holds `survey.json` (`STUB_ADOPT`:
    good, bad-then-good, touch).
  - **README** Commands row and **CHANGELOG** 1.4.0 lines.
  - **Tests.** `test/adopt.test.mjs` (f) now uses `adopt --nope` for the usage, plus new tests (g)–(l):
    - (g) the brief is written on a copy outside the project (no `.env`, no `.git`, no folder path), with Claude

    - (j) an empty answer stops and keeps nothing; ended input exits 1;
    - (k) a project that is not ready stops before any tool runs, and `chooseAgent`'s two errors;
    - (l) a tool that changes the project is caught, and nothing is kept.

### Attempt 2 focus

The builder's attempt 1 was exact. The defect was in the package: `copyTracked` copied every tracked file, so a
project that tracks `.env.local` or a private key by mistake handed it to the AI tool, and through it to the tool's
provider. Exactly these four files change in v2:

- **`lib/adopt.mjs`:**
  - `secretFile(file)` is true for an environment file other than `.env.example`, `.env.sample`, `.env.template` or
    `.env.dist`, for `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, and for `id_rsa`, `id_dsa`,
    `id_ecdsa`, `id_ed25519`;
  - `copyTracked` holds those back and returns `held`, and the start line adds
    `(N held back: environment files and private keys)`;
  - the survey gets `secret_files` and the note `it tracks …, which may hold a secret: DEV_OS never reads or copies
    it` (or `them`).
- **`test/adopt.test.mjs`:**
  - (b) asserts `secret_files` and the note;
  - (g) tracks `.env.example`, `.env.local` and `certs/server.pem`. The copy has the example and neither secret
    file, the start line says `(2 held back: …)`, and no secret value is in `survey.json`.
- **`README.md`** and **`CHANGELOG.md`:** one sentence each on what the copy leaves out.

The other four package files are already on the branch and stay identical.
