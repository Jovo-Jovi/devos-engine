## E35 — Adopting an existing project, step 3: the code a project already has gets a baseline; new or changed code must pass the guards (D-E13, PR-68, engine 1.4.0)

- Phase: E · Risk: 3 · Gate: you. It is a method change: the guards' shared library and runner, the manual, a
  precedent and the reviewer prompt. A project without `devos/baseline.json` behaves exactly as before.
- Builder: grok-4.7 · Effort: medium · Fast: no
- Stages: 1
- Fence version: v1 · 2026-10-31.
- **D-E13, step 3 (the owner's answer of 2026-10-31: "Baseline").** When DEV_OS is added to an existing project,
  the guards would fail on code that was there before. Recording that code once lets every later task pass on what
  it did not touch, while new or changed code is held to the guards.
- **Before this fence (`main` @ 03a743a):** `scripts/guards/run-all.mjs` fails a guard on every finding. There is
  no way to tell a finding the project inherited from one a task added.
- **What the copies change,** for the report:
  - **`payload/files/scripts/guards/lib.mjs`:**
    - `BASELINE_FILE` (`devos/baseline.json`), `BASELINE_SCHEMA` (`devos-baseline/1`) and `BASELINE_GUARDS`
      (`naming`, `design`, `i18n`, `literals`, `imports`);
    - `fingerprint(finding)` drops the line number after the path (`src/a.ts:12 — x` → `src/a.ts — x`);
    - `readBaseline()` returns `null` when there is no baseline, or `{ error }` for invalid JSON, a wrong schema, a
      guard outside `BASELINE_GUARDS`, or a count below 1;
    - `baselineFrom(results, written)` takes the baselined guards' findings, leaving out a guard that crashed;
    - `applyBaseline(results, baseline)` accepts known findings up to their count. A guard whose findings are all
      known passes, with the note `N known (baseline)`;
    - `shrinkBaseline(baseline, results)` lowers each count to what is still found, and never adds.
  - **`payload/files/scripts/guards/run-all.mjs`:**
    - with a baseline, it prints `applyBaseline`'s results;
    - an unusable baseline is a `guard:baseline` FAIL;
    - `--no-baseline` shows every finding;
    - `--write-baseline` writes the file and refuses when it exists (exit 2);
    - `--shrink-baseline` removes what is fixed. It refuses without a baseline, or while a baselined guard
      crashes;
    - neither of the last two may be combined with `--only`. Messages go to stderr with `--json`.
  - **The manual, the precedent and the prompt:**
    - `docs/method/AUTOMATION.md` §5 gets the paragraph **The baseline (PR-68)**;
    - `docs/method/PRECEDENTS.md` gets PR-68 and "Live maximum: PR-68";
    - `devos/prompts/reviewer.md` gets the **Baseline (PR-68)** rule: judge only listed findings, and a change
      that adds to the baseline is a FAIL.
  - **Labels.** `tools/sources.mjs`: E35 on the 5 payload files (`scripts/guards/lib.mjs` gets its first label).
  - **CHANGELOG** 1.4.0: one bullet. The version stays 1.4.0, which is not released.
  - **Tests.** `test/baseline.test.mjs` (new), (a)–(d):
    - (a) the fingerprint, counts, moved lines, an edited line, crashed and never-baselined guards, and shrinking;
    - (b) in an installed project, written once, known findings pass, `--no-baseline`, a new line fails, and a
      second write is refused;
    - (c) shrinking removes the fixed finding and adds nothing; `--only` is refused; a baseline holding `secrets`
      is a `guard:baseline` FAIL;
    - (d) the manual, PR-68 and the reviewer prompt.
- **Why these five guards.** They judge style and structure of code that exists: names, design tokens, catalogues,
  contact literals and module imports. `secrets`, `boundary`, `data` and `services` guard the method's
  non-waivable rules (credentials, visitor data, database grants and RLS, storage and Firebase keys), so an
  adopted project must pass them as they are. The method's own guards (`phases`, `manual`, `config`,
  `design-spec`, `skills`, `fences`, `scope`) check DEV_OS's files, which adoption writes fresh.
- **Protection.** `devos/baseline.json` is under `devos/`, which `surfaces.builder` already denies to a product
  builder. Only the developer, or `devos adopt` (E36), writes it.
- Rehearsed against `main` @ 03a743a. Clean worktree, S1–S2 applied, Linux, Node v22: every line of *Done when*.
  actionlint 1.7.7 with engine-ci's options passes on every workflow.
- Environment: as E01. Never call a real CLI other than git, the network or a real GitHub repository in a test.
- Branch: `task/E35` from `main` @ 03a743a (this fence is on it). Do not run git on the repository.
