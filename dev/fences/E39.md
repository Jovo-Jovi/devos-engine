#### Steps

- **S1 — `lib/adopt.mjs`: the page's questions.**
  - `export function uiReader(read)`. Without `DEVOS_UI=1`, it returns `read` unchanged.
  - With `DEVOS_UI=1`:
    - it first sets `read.isTTY = false` and `read.interactive = true`, as `devos init --plan` does (`lib/init.mjs`).
      Then `interactive(read)` (`lib/setup.mjs`) is true, so the keys are asked, and `readFileKey` takes a file key
      as `base64:`;
    - it returns a wrapper. Before each read, the wrapper writes `"\n"`, then the line
      `::devos-ask {"kind":"line"}`, then returns `await read()`. This is how `uiLine` in `lib/init.mjs` writes
      markers;
    - the wrapper copies `drain`, `pause`, `resume`, `isTTY` and `interactive` from `read`, and sets `.raw` to `read`.
  - `adoptCommand` builds `uiReader(lineReader(process.stdin))` once, and passes it as `read` to `adoptBrief`,
    `adoptInstall` and `adoptPublishCommand`. The `--check` path is unchanged.
  - **Keys** (`adoptPublish`, the loop over `needed`):
    - with `DEVOS_UI=1`, before each key, print the marker `lib/setup.mjs` prints for a key:
      `{ kind: "key", name, where, optional, file, index, total }`. Use a local `uiLine`/`uiAsk` pair, as
      `lib/setup.mjs` has;
    - read the value with `read.raw ?? read`, so no `line` marker goes out for a key;
    - a key's value is never printed, logged or put in a marker.
  - **The end.** With `DEVOS_UI=1`, every path of `adoptCommand` but `--check` ends with
    `::devos-step {"step":"done","code":<its exit code>}`, as `devos init --plan` does, and returns that code.
- **S2 — `lib/hub.mjs`.** The signature becomes `cloneProject(input, base, exec = hubExec, { adopt = false } = {})`.
  With `adopt: true`:
  - the lock call succeeds (status 0) → refused with
    `<slug> is already a DEV_OS project: open it as a current project.`;
  - the lock call fails → the repository is cloned as now. The survey decides the rest.

  The owner or admin check, the folder and reuse are unchanged. Without the option, nothing changes.
- **S3 — `lib/ui-server.mjs`.** The new routes sit behind the existing host, origin and token checks. The adopt routes
  work only in choose mode (no folder given); otherwise they answer
  `400 {ok:false, errors:["This page was opened for one folder. Run devos ui without a folder to add DEV_OS to a project."]}`.
  While a child runs, each answers `409 {ok:false, errors:["A run is going. Try again after it ends."]}`.
  - **`adoptTarget(asked)`**, a folder rule for adoption (`projectTarget` requires a started project, so it is not
    used). It gives one of these errors, or `{ folder }`:
    - `The project folder must be a full path.`;
    - `The project folder cannot be inside the engine's folder.`;
    - `That folder does not exist.` (not a directory).
  - **`POST /api/clone`** takes an optional `adopt` and passes `{ adopt: payload.adopt === true }` as the 4th
    argument.
  - **`POST /api/adopt/check`** `{folder}`, in-process, as `adoptCommand --check` does (import from `./adopt.mjs`):
    - a folder error, or a `gitTop(folder).error` → `200 {ok:false, errors:[<it>]}`;
    - else `200 {ok:true, survey: surveyProject(folder), lines: surveyLines(survey)}`.
  - **`POST /api/adopt/start`** `{folder, agent?}`:
    - `agent`, when given, must match `/^(claude|cursor|codex|gemini)(:[A-Za-z0-9._-]+)?$/`. Otherwise
      `400 {ok:false, errors:["The AI tool must be claude, cursor, codex or gemini, then :model if you want one."]}`;
    - a folder error → `400` with it;
    - after a finished run, it resets `events`, `finished`, `unanswered` and `held`, as `/api/plan` does;
    - then `runDevos(["adopt", folder, ...(agent ? ["--agent", agent] : [])])` → `202`.
  - **The run's kind.** The server keeps `runKind`: `"init"` from `/api/start`, `"adopt"` from `/api/adopt/start`,
    and `null` before any run. `GET /api/state` returns it.
  - **`/api/answer`** accepts `kind: "line"`: a value with `\r` or `\n` → `400` `An answer must be one line.`.
    Otherwise it is written as the other kinds are. `key` is unchanged.
- **S4 — `lib/ui/app.js`** (`app.css` only if a new class needs a rule). Every text is set with `el(..., { text })`,
  never markup. The page never answers by itself: every answer is a click or a typed line.
  - **The entry.** `SCREENS.machine`, in choose mode, has a third choice in the same `choices choices-2` group:
    - title "Existing project";
    - description "Add DEV_OS to a project you already have, on this computer or on GitHub. Nothing changes in it until
      you merge DEV_OS's pull request.";
    - its primary button "Add DEV_OS" goes to `adopt`;
    - the doctor check blocks as it does for "Current project".
  - **`SCREENS.adopt`**, titled "Add DEV_OS to your project". It is outside `STEPS`, as `SCREENS.current` is:
    - **the folder.** The folder finder, or a GitHub address with "Clone" (`POST /api/clone` with `adopt: true`). A
      cloned folder becomes the chosen one;
    - **"Survey it"** (`POST /api/adopt/check`) shows `lines` as text. When `survey.ready` is false, the page shows
      that, and nothing goes on;
    - **when the survey is ready,** a choice of the AI tool that writes the brief. It offers "devos's choice" (no
      `agent`), and each `readyTools()` tool among claude, cursor, codex and gemini (`agent` = its id). Then
      "Write the brief" (`POST /api/adopt/start`) starts the run and listens.
  - **The adopt run.**
    - `app.run.mode = "adopt"` is set when the page starts it, or when `/api/state` says `runKind: "adopt"` at boot;
    - `listen()` keeps `mode` across reconnects, as it keeps `phase`;
    - `liveScreen()` returns `adopting` for an adopt run, whatever it asks.
  - **`SCREENS.adopting`**, titled "Adding DEV_OS":
    - **the log.** The run's log lines, as text, the last in view;
    - **a `line` ask.** A one-line field and "Send". An empty Send sends an empty line: the default, or a stop where
      the question says so. There are quick buttons by the last log line:
      - `yes` and `no` when it contains `(yes/no)` or `Type yes or no`;
      - `yes` alone when it contains `Type yes to`;
      - `accept` when it contains `Type accept`;
      - `1` and `2` when it contains `Choose 1 or 2`;
    - **a `key` ask.** A password field named after `name`, with `where` beside it, sent as the keys screen sends.
      A file key is read from a chosen file as base64. The field is cleared before the request;
    - **the end.**
      - The page's Stop button works as for any run.
      - When `done` arrives, the screen shows the code: 0 is "DEV_OS was added", anything else "The adoption
        stopped".
      - A log line that starts with `devos: the pull request is ` becomes a link only when the rest matches
        `^https://github\.com/[A-Za-z0-9._-]+/[A-Za-z0-9._-]+/pull/[0-9]+$` (`rel="noopener noreferrer"`).
        Otherwise it stays text.
