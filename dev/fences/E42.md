- **Found by the Mawsim test (2026-11-02, 01:06 Cairo).** The guided page on Windows stopped at the blueprint with
  only `devos: the blueprint failed; delete C:\Users\Marco\desktop\devos-projects\mawsim and run devos init again`.
  - **The cause.** `lib/init.mjs` `runBlueprint` starts the agent with the bare name from `toolCommand` (`claude`).
    `lib/spawn.mjs` `resolveTool` then takes the first line of `where claude`. An npm install puts three files in its
    folder: `claude` (a shell script with no extension), `claude.cmd` and `claude.ps1`. `where` lists the file with no
    extension first, `resolveTool` returns it with `viaShell: false`, and Node cannot start it: `spawn … ENOENT`.
  - **Why the page said Claude was installed.** `lib/probes.mjs` `detectAgents` uses `lib/which.mjs` `which`, which
    tries only the PATHEXT extensions and so finds `claude.cmd`. The two resolvers disagree.
  - **Why it hid the cause.** The ENOENT branch (`lib/init.mjs:561`) returns before `explainBlueprintFailure`, so it
    prints no error at all.
  - **Why no test caught it.** `test/harness.mjs` `writeStubs` writes only `claude.cmd` on Windows, never npm's
    file with no extension. `spawnTool` with a bare name is called only at `lib/init.mjs:467`; every other caller
    passes a full path that `which.mjs` found.

#### Steps

- **S1 — One PATH search for Windows** (`lib/spawn.mjs`):
  - New `export function searchPathWin(cmd, pathValue, pathextValue, isFile)`. It is pure; it never reads
    `process.env` or the disk itself.
    - The folders are `String(pathValue ?? "")` split on `;`, trimmed, empty ones dropped, in order.
    - The extensions are `String(pathextValue ?? "")` split on `;`, trimmed, empty ones dropped. When none are left,
      they are `.COM`, `.EXE`, `.BAT` and `.CMD`.
    - For each folder in order, then each extension in order, the candidate is `path.win32.join(folder, cmd + ext)`.
      The first one for which `isFile(candidate)` is true gives `{ path: candidate, viaShell }`, where `viaShell` is
      true when the candidate ends in `.cmd` or `.bat`, in any case.
    - The path is the candidate as built, the extension spelled as in the list. It never returns a file whose name has
      no extension from the list. With no match it returns `null`.
  - `resolveTool(cmd)` on Windows, for a name with no `/` or `\`, uses
    `searchPathWin(cmd, process.env.PATH, process.env.PATHEXT, isFileSync)`, where `isFileSync` is a private helper:
    `statSync(p).isFile()`, and `false` when `statSync` throws. A match gives that result; no match keeps
    `{ path: cmd, viaShell: false }` as today. The rest of `resolveTool` is unchanged.
  - `whereWin` and the `where` call are removed. POSIX behaviour is unchanged.
- **S2 — `which.mjs` uses the same search** (`lib/which.mjs`). The Windows branch of `which(cmd)` returns
  `searchPathWin(cmd, pathEnv, process.env.PATHEXT, (p) => statFile(p) !== null)`, imported from `./spawn.mjs`.
  Its results do not change. The POSIX branch and `run` are unchanged.
- **S3 — A start failure says why** (`lib/init.mjs`):
  - New `export function startFailureLines(command, error, folder)` returns these lines, in order:
    1. `` `devos: ${command} could not start: ${error?.message ?? "no result"}` ``;
    2. only when `error?.code === "ENOENT"`:
       `` `devos: ${command} is not on PATH as a program (an .exe, or the .cmd an npm install adds); run devos agents detect in a new terminal` ``;
    3. `` `devos: the blueprint failed; delete ${folder} and run devos init again` `` (today's text, unchanged).
  - In `runBlueprint`, the branch `if (!result || result.error?.code === "ENOENT")` prints each line of
    `startFailureLines(command, result?.error, folder)` with `console.log`, in place of its one line, then returns `1`
    as now.

- **S5 — The Windows test fixture.** `test/harness.mjs` `writeStubs`, Windows branch: for `claude`, `gh` and each name

- **S6 — The tests.**
  - **`test/version.test.mjs`**: the test becomes `devos --version prints devos 1.4.2` and expects `devos 1.4.2\n`.
  - **New `test/spawn.test.mjs`**, 3 tests. Each builds a `Set` of lower-case Windows paths and passes
    `(p) => set.has(p.toLowerCase())` as `isFile`, as Windows matches names; none touches the disk. Each expected path
    is compared in lower case (the search returns `claude.CMD`: the extension as PATHEXT spells it, as `which.mjs` does
    today).
    - **`spawn.test.mjs searchPathWin takes the .cmd, never npm's file without an extension`**: the set holds
      `C:\npm\claude`, `C:\npm\claude.cmd` and `C:\npm\claude.ps1`; with PATH `C:\npm` and PATHEXT
      `.COM;.EXE;.BAT;.CMD` the result's path is `c:\npm\claude.cmd` in lower case, and `viaShell` is `true`.
    - **`spawn.test.mjs searchPathWin keeps the PATH order`**: the set also holds `C:\bin\claude.exe`. PATH
      `C:\bin;C:\npm` gives `C:\bin\claude.exe` with `viaShell: false`; PATH `C:\npm;C:\bin` gives `C:\npm\claude.cmd`.
    - **`spawn.test.mjs searchPathWin returns null without a PATHEXT match and defaults an empty PATHEXT`**: a set
      holding only `C:\npm\claude` gives `null`; the set of the first test with PATHEXT `""` gives
      `C:\npm\claude.cmd`; PATH `;;C:\npm;` gives the same.
  - **`test/init.test.mjs`**, after `init.test.mjs stops when the blueprint fails`, 1 test:
    **`init.test.mjs startFailureLines names why the agent could not start`**:

    - `undefined` gives two lines, the first `devos: claude could not start: no result`.
