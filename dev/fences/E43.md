#### Steps

- **S1 — The token, tried three times** (`payload/files/scripts/devos/report.mjs`):
  - `TIMEOUT_MS` becomes `20000`.
  - New `export async function oidcResult(audience, env = process.env, { tries = 3, waits = [2000, 5000], sleep, timeoutMs = TIMEOUT_MS } = {})`
    returns `{ token, reason }`. `sleep` defaults to a `setTimeout` promise.
    - Without `ACTIONS_ID_TOKEN_REQUEST_URL` or `ACTIONS_ID_TOKEN_REQUEST_TOKEN`: `{ token: null, reason: "permission" }`,
      and no request.
    - Otherwise up to `tries` requests, as `oidc()` makes today. Before try `n` (from the second), it awaits
      `sleep(waits[n - 2])`.
    - A try fails with the reason `timeout` (the abort of `timeoutMs`), `network` (any other fetch error), `HTTP <status>`
      (a reply that is not ok) or `no token` (an ok reply with no string `value`).
    - The first token gives `{ token, reason: "" }`. After the last failed try: `{ token: null, reason: <its reason> }`.
  - `oidc(audience, env)` stays, and returns `(await oidcResult(audience, env)).token`. `history` keeps using it.
- **S2 — The messages name the cause** (same file):
  - **`link`** uses `oidcResult`. With the reason `permission`, the line stays exactly
    `devos report: no OIDC token (the job needs id-token: write; a fork has none); nothing sent`. With any other reason:
    `` `devos report: GitHub gave no OIDC token after 3 tries (${reason}); nothing sent, and the next run asks again` ``.
    Both write `{ "status": "none" }` as now.
  - **`flush`**, before sending, with `N` waiting events:
    - not linked: `` `devos report: not linked (${status}); ${N} events not sent. They stay in this run's evidence: re-run this report job once the project is linked` ``;
    - reason `permission`: `` `devos report: no OIDC token (the job needs id-token: write; a fork has none); ${N} events not sent` ``;
    - any other reason: `` `devos report: GitHub gave no OIDC token after 3 tries (${reason}); ${N} events not sent. They stay in this run's evidence: re-run this report job to send them` ``.
  - **`flush` stops at the first event the registry does not answer** (`post` gives status `0`: `timeout` or
    `network`). That event gets `attempts + 1` and its `last_error`, as today. The events after it are not posted and
    keep their fields, and they count in `kept`. The tally line is unchanged.
