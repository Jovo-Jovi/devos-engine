## E45 — A weekly limit waits days, not an hour; a builder whose tool is out moves to a fallback builder of another tool; a model variable never strands a role; a resume survives a failed label removal, and the supervisor may restart a task (engine 1.4.5, PR-76)

- Phase: E · Risk: 3 · Gate: you. It changes the method: the reset parser, the builder's outcome, the model
  variables and the cycle workflow. Every change adds a way to keep going; none takes a check away.
- Builder: grok-4.7 · Effort: high · Fast: no
- Stages: 1

  fixes the Mawsim test found into E45, before local mode).
- **Found by the Mawsim test (owner, 2026-11-03).** Cursor said
  `Weekly usage limit reached. It resets in 5 days.` Then:
  - **One hour, not five days.** `limits.mjs` `parseResetTime` reads `resets in 2h 15m` and `resets at 18:00`, but no
    days. The text parsed as nothing, so `notBefore` used `resume.default_wait_minutes` (60). Since 16:25 UTC, T06
    attempt 3 was re-run every hour, and each run hit the limit again (Mawsim runs 41674128270 … 41714515117:
    `Waiting 59 minutes, until 2026-11-03T20:38:57Z`).
  - **Nothing else could build.** The runner tries only the builder's own tool (PR-53, PR-64), and the project
    page's Models list offers only that tool's models (PR-63). The Claude models Cursor lists use Cursor's own limit.
  - **A model variable can strand a role.** `withModelOverrides` puts `DEVOS_BUILDER_MODEL` on the default builder
    whatever its tool. E43 sets that variable in every new project. If the default builder moves to Claude, Claude is
    handed a Cursor model, and with no next model nothing can run.
  - **A resume stopped by a label (2026-11-04).** After its wait, Mawsim's `wait-and-resume` job ran
    `gh pr edit 9 --remove-label "devos:quota-wait"`. GitHub returned `GraphQL: Something went wrong` but removed the
    label, and `bash -e` ended the step before `gh workflow run`. T06 was left with no label and no run (run
    41804927121, job 126490451769; `devos-cycle.yml` line 1184). `devos-wait`, `devos-resume` and `devos-intake`
    have the same line before their dispatch.
  - **The supervisor could not repair it.** It found the incident and ran `gh workflow run devos-cycle.yml`, and
    GitHub refused it: `HTTP 403: Resource not accessible by integration`. Without `DEVOS_PAT`, its token has
    `actions: read` (`devos-supervisor.yml` line 39), while its re-dispatch and re-run repairs need `actions: write`.
- **The design** (reviewer, rehearsed on a copy of `main` @ e6905be):
  - **A fallback builder, by opt-in.** `agents.fallback_builder` names a pool builder whose tool is not the default
    builder's. It is used only when every account and model of the run's tool is out until later than
    `resume.inline_wait_max_minutes`.
  - **Carried by a pull-request label, not a dispatch input.** `devos-cycle` already has 10 dispatch inputs, and
    actionlint 1.7.7 refuses an 11th. A label also stays on every later slice, attempt and resume of the task with no
    input to carry. When the task merges, the next task starts on the default builder again.

#### Steps

- **S1 — Days in a reset** (`payload/files/scripts/devos/limits.mjs` `parseResetTime`):
  - The relative form also reads days, before hours and minutes:
    `/(?:resets?|try again)\s+in\s+(?:(\d+)\s*d(?:ays?)?)?\s*(?:(\d+)\s*h(?:ours?|rs?)?)?\s*(?:(\d+)\s*m(?:in(?:utes?)?)?)?/i`.
  - With days only (no hours, no minutes) the reset is `days × 24 h − 12 h` from now, and never less than 60 minutes:
    a stated "5 days" may be rounded, and an early resume reads the next, finer message.
  - With hours or minutes too, it is exact: `days × 24 h + hours + minutes`.
  - Every other form behaves as today. The doc comment names `resets in 5 days` and the half day.
- **S2 — A model variable keeps the configured model next** (`payload/files/scripts/devos/lib.mjs`
  `withModelOverrides`):
  - New private `keepConfigured(agent, chosen)`. When `agent.model` is set and differs from `chosen`, the agent's
    `fallback_models` becomes `[agent.model, ...its fallback_models without agent.model and chosen]`, cut to 4. It is
    called just before the reviewer's, the existing light reviewer's and the default builder's model is replaced.
  - A light reviewer the variable creates gets no `fallback_models`, as today. A variable equal to the configured
    model changes nothing. The notes are unchanged.
- **S3 — `agents.fallback_builder`** (`payload/files/scripts/devos/agents.mjs`):
