- **The reviewer's findings on ca6cd6c.** They are true:
  - **The page cannot make a local project.** `buildPlan` (lib/ui/app.js:567) sends no `cycle`, so every plan from
    the page takes the GitHub path. `validatePlan` already accepts `"cycle": "local"` (E46).
  - **The page's engine check is GitHub's.** The state's `doctor` is `{ ok: doctorCommand() === 0 }`

    cycle, and the review screen shows them as `Keys you will paste after approving`.

    (lib/init.mjs:1072), so it can start a project in a folder named `--help`. The usage text (bin/devos.mjs:37-60)
    lists neither `--local` nor a help command.
  - **There is no `devos doctor --local`.** `doctor` takes no argument (bin/devos.mjs:69).
  - **E46's two remaining follow-ups** (`dev/reviews/E46-a1-remote.md`, Owner attention):
    - `localSetup` asks the backup question even when the project already has an `origin`, and a yes then fails;
    - `devos verify` lists a missing gh as a `block` (`STOP`) for a local project (lib/verify.mjs:384, 409).

  - **The local path removes parts of screens, not steps.** It leaves out the link (contract), the visibility (details)

- **S2 — `devos init --help`** (`lib/init.mjs`, `initCommand`). Before anything else, an argument `--help` or `-h` in

  ```
  devos init: set up a new project in a new or empty folder (the current folder when none is given)

    devos init [folder]
      Automated development (GitHub): AI agents build and review each task on GitHub, and you merge.
      Needs the GitHub CLI, signed in with gh auth login.
    devos init --local [folder]
      Local development (this computer): you build each task in your IDE from its fence, on its own
      branch, and it is reviewed before you merge. Needs only Node.js 22 or newer and git.
      No Control Tower link, visibility or hosting question. The project ends with the approved
      blueprint, README.md, SETUP.md and the first commit. A last question can add a private GitHub
      repository as a backup, where only CI runs (DEVOS_PAUSED is set to true before the first push).
    devos init --continue [folder]
      Pick up a started project where it stopped, as devos continue does.
    devos init --plan <file> [folder]
      Set up from a plan file, as the guided page does.

  devos ui offers the same two ways of working on its first screen.
  ```

  Then, without `--plan`, an argument that starts with `-` and is not `--local` or `--continue` prints
