  `devos remove` removes only the files DEV_OS installed and still owns, keeps the project's documents, fences,
  reviews and `devos/answers.json`, keeps and lists a DEV_OS file the developer edited, lists GitHub secrets,
  `DEVOS_*` variables, labels and the Control Tower link and deletes them only after a typed yes, lands as a
  `devos/remove` branch and pull request, and deletes a failed adoption's `devos/adopt` branch: on the computer, and
  on GitHub after a yes.
- **How it works: two runs.**
  - **With an engine lock** (`devos/engine.lock.json`), on a clean tree with a branch checked out:
    - it removes, on a new branch `devos/remove`, every file of the lock that git tracks and whose hash is still the
      lock's (at its `at` when the project keeps it elsewhere), with the lock and `devos.config.json`, and prunes the
      folders it empties;
    - it keeps the project's own files, the settings written for it at setup (`devos/project.json`,
      `devos/prices.json`, two `.cursor/rules/`), every DEV_OS file the developer edited (listed), `docs/method/`
      (the fences and reviews cite it), and `.gitignore` and `.gitattributes` (the project still uses them);
    - it lists all this and goes on only on `yes`. It commits `DEV_OS remove (engine <version>)`, pushes, opens the
      pull request "Remove DEV_OS" and sets `DEVOS_PAUSED` to `true` so the cycle starts no new task. With
      `--local`, the commit only;
    - a failure before the commit rolls back: the branch is deleted and nothing changes.
  - **Without a lock** (after that merge, or after an adoption that was never merged), it lists what is left:
    - the branch `devos/adopt` on this computer: deleted after `yes`, with its worktree;
    - on GitHub, read from origin's configured URL: the branch `devos/adopt`, DEV_OS's secrets (the agents' keys
      and `DEVOS_*`), every `DEVOS_*` variable (`DEVOS_REPORTING` and `DEVOS_STATE` are named as the Control Tower
      link) and every `devos:` label. All are deleted only after a typed `yes`;
    - the keys of the project's services that setup asked for (hosting, database, storage) are asked apart, because
      the product may still use them. A secret DEV_OS does not know is never touched.
