- **What changes:**
  - **The fence line.** `- Dependencies: \`<package>\` · …`, or `- Dependencies: none`: every package the task may add
    to a manifest. `fence-check.mjs` checks it when present (a name, not empty, no repeat). A fence without the line
    names none, so a fence written before PR-85 keeps passing `fence-check`.
  - **`guard:deps`** (`scripts/guards/deps.mjs`, in `run-all.mjs`). In a task run, the branch against its base plus
    the working tree, as `guard:scope` reads it:
    - each `package.json` that changed is compared with the base: a package it gains in any dependency section,
      that the line does not name, is a finding. A version change or a move between sections gains nothing. A
      manifest the task creates (the scaffold) holds the stack's packages and is not named;
    - when a manifest or `pnpm-lock.yaml` changed, `pnpm audit --audit-level high --json` runs. Each high or critical
      advisory is a finding. An audit that does not answer (asked twice) is a finding, and so is a missing lockfile.
      A waiver is `pnpm.auditConfig` in `package.json`, which pnpm applies, with the owner's recorded decision;
    - an added package whose installed `package.json` names a copyleft licence (GPL, AGPL, LGPL, MPL, EPL, EUPL,
      CDDL, OSL, SSPL, CPAL, CC-BY-SA) is a warning in the guard's note, never a finding;
    - N/A outside a task run (no `TASK`), without the task's fence, and for a toolchain other than Node; a task that
      changes no manifest or lockfile passes with no audit.
  - **Who writes and reads the line:** the blueprint (every fence; T01 names what it adds beyond the stack's `create`

### For the owner, after the merge

- **Projects pick it up with `devos upgrade`** (1.10.0, a pull request). From then on, a task that adds a package its
  fence does not name fails `guard:deps`, and the reviewer reissues the fence with the package named when it is
  needed. A fence written before the upgrade names none, so only a task that adds a package is affected.
- **The reviewer's readings, yours to change:**
  - **The audit runs only when the task changes a manifest or `pnpm-lock.yaml`.** An advisory published later never
    stops an unrelated task, and `main`'s own CI (no `TASK`) never runs it. The first task that touches the
    dependencies of a project with old advisories must fix or waive them.
  - **All dependencies are audited,** dev dependencies too, as the owner said "blocks high and critical".
  - **An audit that does not answer fails the gate** rather than passing it unseen (the registry is asked twice).
  - **A manifest the task creates is the scaffold's:** its packages are not named, but they are audited and their
    licences read. T01's line names what it adds beyond the stack's `create` commands.
  - **Copyleft is a warning only** (the owner's word), listed in the guard's note for the reviewer, with weak copyleft
    (LGPL, MPL, EPL) included.
- **Node first:** Python, Go and Dart projects get N/A from `guard:deps` until a later task adds their manifests and
  audits (`uv`, `go`, `dart pub`).
