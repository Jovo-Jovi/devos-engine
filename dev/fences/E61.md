- **What changes:**
  - **`/devos accept [note]`** on a task PR, by an owner, member or collaborator (job `accept` in
    `devos-intake.yml`, no agent). `scripts/devos/accept.mjs` writes `docs/reviews/Tnn-aN.md` (N: one past the
    task's highest attempt, from its review files and its `Tnn aN:` commits). The file starts `VERDICT: PASS`, says
    no attempt N was built or reviewed, cites the last review and quotes the note. The script also ticks the row
    `PASS aN — docs/reviews/Tnn-aN.md`, so `guard:phases` passes.
    - It refuses a ticked task, a task not in `docs/PHASES.md`, and a product task after an open one (tasks go in
      order).
    - On an **open** PR the commit goes to the task branch (with `sync-main.sh` first); merging the PR starts the
      next task.
    - On a PR **merged by hand**, it goes on a new branch `devos/accept-Tnn` with a pull request labelled `devos`,
      whose merge starts the next task.
    - A PR closed without a merge is refused.
    - The comment's text reaches the shell only through the environment.
  - **No second build of a hand-merged task.** `devos-advance` reacts to `devos/accept-` merges too. When a merged
    `task/Tnn` is still the next open task (merged without a PASS), it comments that the cycle does not build it again
    and names `/devos accept`, and dispatches nothing. The halt notes (`verdict.mjs`) name both ways on: `/devos
    revise` and `/devos accept`.
  - **Screenshots at 2×.** `screens.mjs` opens every capture page with `deviceScaleFactor: 2` (`SCALE`):
    - the settled and reduced-motion screenshots are 2560 px wide at 1280 and 780 at 390; the filmstrip stays at
      the screencast's 1×;
    - `motion.json` records `screenshot_scale: 2`, and the evidence summary says to halve a length for CSS px;
    - the reviewer prompt and the `devos-compose-ui` skill say so;
    - the self-test checks the PNG widths.
  - **A server error is tried again.** `limits.mjs` `serverError` reads only the CLI's own error, as for an unusable
    model (PR-64):
    - it counts an HTTP 5xx, a dropped connection (`ECONNRESET`, `ETIMEDOUT`, `EAI_AGAIN`, `socket hang up`) or an
      error marked retriable;
    - it does not count "non-retriable", "not retriable", `retriable: false`, a finished run or a watchdog stop;
    - `limit-check.mjs --server` and `accounts.sh` `devos_server_error` call it.
    `devos_server_wait` gives 30, 60, then 120 seconds, then nothing. Every builder run (Cursor, Claude Code, Codex,
    Gemini), every review run and every planning run (`plan-agent.sh`) then runs again in place, up to three times,
    before its limit and unusable-model checks. A builder retry needs 10 minutes left of its 72, and tells the agent
    to continue from its partial changes.

    workflow rows, `accounts.sh`, `screens.mjs`, §9. `guard:manual` checks 126 names (a new script and a new

### For the owner, after the merge

- **Projects pick it up with `devos upgrade`** (1.11.0, a pull request). Mawsim, on 1.6.0, gets E59's gate, E60 and this
  together.
- **The reviewer's readings, yours to change:**
  - **The acceptance is attempt N+1, not a rewrite of the last review.** The FAIL that stopped the task stays as it
    was, and the new file says no attempt was built. This is T17-a4's own form.
  - **On an open PR the acceptance is a commit on its branch, and you still merge.** The runner never merges a task you
    accepted; your merge is the sign-off, as at a gate.
  - **A hand-merged task with its row open is never built again on its own.** To build it again, run `devos-cycle`
    for it by hand.
  - **Tasks are accepted in order:** a product task after an open one is refused, as `guard:phases` would refuse its
    tick.
  - **Only the screenshots are 2×.** CDP's screencast gives the filmstrip frames at 1× in headless Chromium, and
    the filmstrip is for motion, not measurement. The README screenshot the builder copies from
    `.devos/screens/<state>-1280.png` is now 2560 px wide.
  - **Three retries, after 30, 60 and 120 seconds,** for any agent run: a little over 3.5 minutes at most. After that
    the run's usual handling decides (a limit parks, an unusable model moves on, anything else stops as before).
