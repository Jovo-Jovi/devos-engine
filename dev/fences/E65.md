### What the package does

- **An adoption's AI tool reads and writes files, as far as the tool allows.** An adopted project's text may not be
  the developer's own, so `devos adopt` treats it as untrusted input.
  - **Claude Code**, in the brief and the document rounds:
    - `--allowedTools Read,Glob,Grep,Write,Edit` and `--disallowedTools Bash,PowerShell,WebFetch,WebSearch`
      (PowerShell is Claude Code's shell on Windows);
    - `--setting-sources user --strict-mcp-config`: no project settings, hooks or MCP servers;
    - `--settings <staging>.fence/claude-settings.json`:
      - reads kept to its folder (`permissions.blockReadsOutsideWorkingDirectories`);
      - the same four tools denied, and every secret file's read;
      - `claudeMdExcludes`: none of the project's `CLAUDE.md`, `CLAUDE.local.md` or `.claude/rules/` files, whose `@`
        imports Claude Code would read at launch, outside its tools.

      The file sits beside the staging folder, outside both rounds' folders, and is written afresh by each adoption.
    - It needs Claude Code 2.1.257 or later. An older version, read from `claude --version`, stops the adoption; an
      unknown one does not.
  - **Cursor** (`.cursor/cli.json`, `ADOPT_CURSOR_DENY` first in both kits):
    - `Shell(*)`, then 19 commands named one by one in case a glob is not read (the shells, `node`, `python`, `git`,
      `curl` among them), `WebFetch(*)` and `Mcp(*:*)`;
    - in the brief round, it reads the copy and writes `brief/` only;
    - in the document rounds, the blueprint kit loses `Shell(node)`, `Shell(ls)` and `Shell(cat)`, and every secret
      file's read is denied.
  - **Gemini:** `--approval-mode auto_edit` in the document rounds too (it was `yolo`), and in both rounds
    `--admin-policy <staging>.fence/gemini-policy.toml`, which denies `run_shell_command`, `web_fetch` and
    `google_web_search`. A user or project policy cannot override an admin one.
  - **Codex:** unchanged (`--sandbox workspace-write`, as the audit found it). See limitation 1.
  - **The project's own tool configuration stops the adoption** when the chosen tool would load it and run what it
    names: `.cursor/mcp.json` for Cursor, `.gemini/` for Gemini, `.codex/` for Codex. The names are read with case
    aside, and a tracked link in a folder's place counts. The message names the files and offers `--agent claude`.
    Claude Code loads none of the project's. The check runs before the brief round and again before `--install` asks
    for anything; an older copy of DEV_OS, where no tool runs, skips it.
  - **Nothing a round leaves for the next one to run.** Before each brief round, devos removes `ROUND_CONFIG` from the
    staging folder: `.gemini`, `.codex`, `.claude`, `.mcp.json`, and Cursor's `mcp.json`, `hooks.json` and `hooks/`.
    In the document rounds, such a file is already a stray that stops the adoption.
- **devos runs what an adoption needs.** After each document round, `checkAdoptDocs` writes `devos.config.json` from
  `devos/project.json` (`config.mjs --write`) before `fence-check` and the guards; a failure goes to the next round.
  `lib/data/adopt-blueprint.md` tells the tool it runs no command, opens no web page and reads no secret file.
- **One list of secret files (L1).** `SECRET_GLOBS`:
  - environment files: `.env`, `.env.*`, `.envrc`;
  - keys: `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore` and the four `id_*` keys;
  - credentials: the Firebase admin-SDK and service-account names, `serviceAccountKey*.json`, `*credentials*.json`;
  - Terraform: `*.tfvars`, `*.tfstate`, `*.tfstate.*`;
  - tokens: `.npmrc`, `.netrc`, `.pgpass`.

  With `SECRET_EXAMPLES` (`.env.example`, `.sample`, `.template`, `.dist`), it drives three things:
  - `secretFile`: never read or copied by adopt;
  - the tools' read-deny rules;
  - `ADOPT_IGNORE`, which is the head of the shipped `.gitignore`. So the engine's `.gitignore` now lists them all.
  One with no secret in it can still be committed with `git add -f`.
- **`devos init` is unchanged:** its blueprint keeps web research and its two commands, since the words there are the
  developer's own (the audit's Fit). The payload's Cursor blueprint kit is unchanged.
- **Records:** CHANGELOG `1.13.0 — Unreleased` (two bullets); `payload/manifest.json` (`.gitignore`).

### Limitations (reported)

1. **Codex keeps its own sandbox.** `workspace-write` lets it run commands, without network, and read files outside
   the project (your home folder's keys, say). It could write what it read into a document, which stays on the local
   branch `devos/adopt` until you answer yes to push. Codex has no setting that takes its shell away without taking
   its writes too. For a project whose text you did not write, choose Claude Code; the CHANGELOG says so.
2. **Gemini's fence is untried on a real Gemini** (no live test until every task is done). `--admin-policy` follows
   Gemini's policy-engine documentation; an older Gemini that does not know the flag stops with its own error.
   Supplemental admin policies are ignored when the computer has system policies in Gemini's standard admin folder.
   Gemini's reads stay in its folder, but a secret file the project tracks is not read-denied to it there.
3. **Cursor's denies are untried on a real Cursor.** `WebFetch(*)` and `Mcp(*:*)` are the forms Cursor's permissions
   reference documents, and its `Shell(…)` takes globs; the named commands back up the shell only. Cursor's reads are
   not kept to its folder: its reference says an absolute path can reach files outside the project, and the secret
   read-denies are relative to the folder. As with Codex, what it read could only reach a document on the local
   branch.
4. **Claude Code's version is read from `claude --version`.** When it prints none, nothing stops the adoption, and an
   older Claude Code would ignore `blockReadsOutsideWorkingDirectories`. `claudeMdExcludes` follows Claude Code's
   memory documentation and is untried here; the documentation does not say whether deny rules reach an `@` import.
5. **An upgrade does not merge `.gitignore`.** A project whose `.gitignore` is no longer DEV_OS's copy (every adopted
   project's) sees it listed as a conflict in the upgrade pull request, as for any earlier change to it; the new lines
   are added by hand. The CHANGELOG says so.
6. **Case:** `secretFile` ignores case; git matches as `core.ignorecase` says (on by default on Windows and macOS,
   off on Linux). On Linux, `A.KEY` is held back by adopt but not ignored by git. The tools' read-deny rules are
   written in lower case, so a tracked `.ENV` in the document rounds may not be denied; the brief's copy holds it
   back.
7. **Ignoring is not untracking.** A secret file a project already tracks stays tracked; adopt still holds it back
   from the brief's copy and denies its read to Claude Code and Cursor. OWASP advises committing a token-free
   `.npmrc`; with DEV_OS's `.gitignore` that takes `git add -f`.
8. **Not yet run with the real tools** (the owner, 19:06: no live test until every task is done).
