### What the package does

- **N5: the deploy's CLIs and secrets.**
  - **The lockfiles.** New `devos/tools/vercel/` and `devos/tools/firebase/`, each a `package.json` and a
    `package-lock.json`, lock `vercel@65.2.0` (385 packages) and `firebase-tools@15.34.1` (635 packages). Every package
    comes from `registry.npmjs.org` with a `sha512` integrity hash.
  - **The new step.** "The deploy's CLIs, from their lockfiles (no secret, no install script)" runs after the guards. It
    holds no secret and does this:
    - `npm ci --prefix devos/tools/<tool> --ignore-scripts`: always for vercel, and for firebase only when the Firestore
      step will run;
    - it refuses an installed version that differs from `pins.mjs` (`tool_versions`).
  - **The steps that use them.** The Firestore step runs `devos/tools/firebase/node_modules/.bin/firebase`, with no
    `npm install -g` any more. The Deploy step runs `devos/tools/vercel/node_modules/.bin/vercel` for pull and build,
    with no `npx` any more, and passes it to `vercel-deploy.sh` as `DEVOS_VERCEL_BIN`.
  - **The secrets.** The job's level holds none: `VERCEL_TOKEN`, `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` are in the
    Deploy step only. So the project's `pnpm install`, the guards and the Firestore step no longer see the Vercel token.
  - **`vercel-deploy.sh`.** It runs the CLI that `DEVOS_VERCEL_BIN` names, or PR-93's pinned `npx` when run by hand. It
    uses a command array, never `eval`.
- **C4: the cycle wakes the supervisor.** A run the cycle started with the workflow's own token fires no
  `workflow_run`. So a new job, `notify-supervisor`, starts the supervisor:
  - it needs `resolve`, `work` and `publish`;
  - it runs only when all of these hold: the run's actor is `github-actions[bot]`; `DEVOS_SUPERVISOR` is not `off`; the
    project is not paused; and a job failed or was cancelled;
  - its only permission is `actions: write`;
  - it runs `gh workflow run devos-supervisor.yml --ref main -f after_run="$RUN_ID"`.

  The supervisor gets an `after_run` input. A new step, "Wait for the cycle run that called", checks the input is digits
  only, then waits up to 5 minutes for that run to finish before the scan. A run you or your PAT started is not
  notified twice: `workflow_run` already sees it.
- **C5: the run's task and the evidence.**
  - **The task.** A run titled without its task (`devos next · attempt 1`) takes its task and attempt from its
    artifacts' names (`devos-T28-a1`, `devos-T28-a1-work`).
  - **The log.** The evidence is the failed steps' log (`gh run view <id> --log-failed`), else the job's log. Either way
    it is cut at the last `##[error]`, not at the clean-up after it.
  - **An unreadable log.** If no log can be read, the evidence says why, in the form `(the run's log could not be read:
    <gh's first error line>; …)`. Today it is silently empty: both of mawsim's diagnoses had no log at all.
- **F1: Claude's text shown inert.**
  - **The report.** For an AI-diagnosed incident, "What happened" reads "see Claude's reading below". The cause, the
    explanation and the steps it suggests all sit in one fenced block under the heading "**Claude's reading of the
    logs** (unverified: the logs include text the builder wrote)".
  - **The proposal.** A proposed issue's title now sits inside the fence, beside its body.
  - **The result.** No link, image or mention from the model renders or notifies anyone. "Steps for you" is kept only
    for text the supervisor wrote itself.

### Limitations (reported)

1. **`vercel build` still runs the project's code with the Vercel token in its environment:** the CLI needs it for pull
   and build. What changed: the install, the guards and the Firestore step no longer have it, and the CLI's own tree is
   locked and installed with no script.
2. **firebase-tools runs with the service account,** as it must. Its optional native `re2`, used for hosting rewrites,
   stays unbuilt with scripts off. The Firestore rules deploy does not load it (`firebase --version` and the rules path
   ran).
3. **The weight:** every project carries the two lockfiles (about 450 KB). A deploy installs about 300 packages, plus
   about 630 with Firebase, which adds roughly 30 to 60 seconds.
4. **A project that overrides `tool_versions` for vercel or firebase** has its deploy refused, with the reason, until its
   lockfiles match: `devos upgrade` brings the engine's.
5. **A failure inside `wait-and-resume`** (a parked run) is still seen only through the supervisor's schedule.
6. **The supervisor a failed run starts waits at most 5 minutes** for that run to finish, then scans anyway.
7. **Why mawsim's logs were empty is not proven.** The evidence now shows either the log or the exact reason, so the
   next failure says which.
8. **Not yet run on GitHub:** see "For the owner, after the merge".
