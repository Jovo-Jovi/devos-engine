### What was wrong (the owner's notes, against the code)

- **The model list starts at 88.** The adoption screen was a terminal in the page: the engine's output and one answer
  box. The output showed its last 200 lines, and the agents' menus are printed as numbered lists of every model, so the
  top of a list fell off.
- **Not like the onboarding.** Every question (the brief, the contract, the link, the agents, the push) was a line of
  that output, answered by typing.
- **The end.** A one-line notice, "DEV_OS was added", above the output.
- **No keys step.** Only keys GitHub lacks were asked, inline. The Control Tower had them all, so nothing showed, and the

- **The sidebar.** One step list, the new project's, for every flow.

### What the package does

- **Each question says what the page draws** (`lib/menu.mjs`, `lib/adopt.mjs`). The answer is still the one line a
  terminal reads, so `/api/answer` and its checks are unchanged, and `devos adopt` in a terminal prints and reads exactly
  as before.
  - `showOnPage(read, form)` sets `read.next`. `select`, `multiSelect`, `confirm` and `text` set it before each read,
    with the title and every option's label: `choice`, `choices`, `confirm`, `text`.
  - Adopt sets the others: `brief` (the brief's text, at most 40 000 characters), `contract`, a `confirm` for "Add
    DEV_OS now?", the Control Tower link (no default, `choose: true`), the tasks a handed-over project ticked, and the
    push. It also names each question's step (`read.step`): brief, contract, link, agents, deploy, write, keys, publish.
  - `uiReader` sends the form once with the next question, as `::devos-ask {…form, "kind":"line", "step":…}`.
  - `::devos-step {"step":"adopt","at":…}` says where the adoption is between questions:
    - `brief` (the tool and model);
    - `write`;
    - `keys`: every key the cycle needs as name, where, optional and present, plus the Vercel items (title, names,
      steps). Names only, never a value;
    - `publish`;
    - `finish`, with the result: the pull request, ready or the missing settings, the first task and its start
      command, the keys left to set, the Vercel items; or "nothing was pushed".
- **The page** (`lib/ui/app.js`, `lib/ui/app.css`):
  - **Its own steps** in the sidebar: Your project (This computer, Project and survey, Brief), DEV_OS (Contract,
    Control Tower, Cycle agents, Deploy, Add DEV_OS), GitHub (Keys, Pull request, Done), with a title block of the
    project, its stage and stack.
  - **The adopt screen:** "How adding DEV_OS works" in four steps; the survey as facts, with its full text behind a
    disclosure; a ready notice.
  - **One screen per question.**
    - Choices: every option, grouped by tool, with a search and a count. "On your account" is shown as a badge. A
      choice of none is sent as `,`, which `multiSelect` reads as none.
    - The brief: as a document. Keep it, ask for changes, or stop.
    - The contract: the same text and checkbox as a new project's.
    - The link: two cards, neither chosen.
    - The others: their text, with their own two buttons.
  - **Keys:** "Key N of M" and the hidden field as before. Under them, every key with "On GitHub", "Needed" or
    "Optional", and "Set these in Vercel yourself" with each item's steps. The push screen shows the same lists.
  - **Between questions:** what the engine is doing, with the agent's live steps.
  - **The end:**
    - ready: the pull request as a card, "What happens next" (read it, merge it yourself, the first task and its start
      command), the keys left to set and the Vercel items;
    - otherwise: what is still missing, or "Nothing was pushed", each with its command;
    - every end offers "Open the project's page", "Adopt another project" and "Close DEV_OS".
  - **The engine's output** is kept whole (5000 lines; a new project keeps 500). It sits behind a closed disclosure, and
    fills only while it is open.
  - **Motion:** screens arrive as before; facts and key rows stagger in; the reduced-motion rule already stills them.
- **Records:** the README's adopt section says what the page shows; the CHANGELOG entry `1.13.4 — Unreleased`; version
  1.13.4 in `package.json`, `README.md` and `payload/manifest.json`; the tests that name the version (the upgrade
  scenarios now go from 1.13.4 to 1.13.5).
