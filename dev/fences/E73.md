### What the package does

- **1. The production address is a GitHub variable, asked for only when it is read.**
  - **What reads it:** the deploy's smoke test reads `vars.DEVOS_PRODUCTION_URL`, and only when `deploy.probe` is
    `production` (else `deploy.production_url_fallback`). That is unchanged.
  - **The item, before:** the setup item `production-url` asked every Vercel project for a Vercel Production
    variable. Nothing read it there, and the deploy stopped until it existed.
  - **The item, now:** it has a new kind, `address`: a repository variable the human sets, checked for the form
    `https://…`, never set by DEV_OS. `devos init` and `devos adopt` set only kind `variable`, so they never set it.
  - **When it applies:** a new condition, `probe:production`: `deploy.probe` is `production` and
    `deploy.production_url_fallback` is empty. It is in `setup-check.mjs` and, for `SETUP.md` and the guided page, in
    `lib/setup.mjs`.
  - **What changes for projects:** a project that probes its deployment (the default) is no longer asked for it. One
    that probes production with no fallback is now stopped before the deploy, where it used to fail at the smoke
    test.
- **2. Adopting an older copy keeps the project's own settings.**
  - **Setup items:** the items of the copy's `devos/setup.json` that name a setting DEV_OS's never names move to
    `docs/setup-items.json`, which the setup check already reads.
    - An item keeps only those names, and one with a DEV_OS item's id becomes `<id>-own`.
    - An item the project's `docs/setup-items.json` already has stays as it is, after that file's items.
    - An entry that is not an item stops the adoption, naming it.
  - **The smoke-tested address:** when the copy's settings have no `deploy`, the address its own `devos-deploy.yml`
    smoke-tested becomes `deploy.probe` `production` with `deploy.production_url_fallback`. That address is an
    `https://` host in the expression that picks the production target's URL.
  - **Reporting:** the output and the pull request name both, and `devos/answers.json` records the ids under
    `adopted.copy.setup`.
- **Records:** the CHANGELOG entry `1.13.6 — Unreleased`; version 1.13.6 in `package.json`, `README.md` and
  `payload/manifest.json`; the tests that name the version (the upgrade scenarios now go from 1.13.6 to 1.13.7).
