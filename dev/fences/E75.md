### What the package does

- **Where each tool's list comes from (`lib/model-check.mjs`):**
  - **The tool's own list,** for a tool that lists its models: Cursor (`agent models`), GLM and Muse.
  - **The provider's models API,** for Claude Code (Anthropic), Codex (OpenAI) and Gemini (Google), when the key is
    already in the environment: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` or `GOOGLE_API_KEY`.
    - The key goes only to its provider's fixed address, in that provider's header.
    - It is never printed, returned to the page or kept.
    - Image, audio and embedding models are left out.
  - **Else the engine's list** (`lib/data/tools.json`), with a note naming the key or tool that would make the check
    live.
- **How a model is judged against that list:**
  - **Its line** is its family plus what follows the version, with a dated snapshot's date left out:
    `claude-fable-5-1` is the `claude-fable` line at 5.1, and `gpt-5.6-sol` is `gpt …-sol` at 5.6.
  - **An effort or speed ending** (`-high`, `-xhigh-fast`, `-fast-low`, as `scripts/devos/builder-model.mjs` reads them)
    is not part of what is offered: a list with `grok-4.7-high` offers `grok-4.7`, because the cycle adds the fence's
    effort to the role's model.
  - **The verdict:**
    - *current*: the newest of its line;
    - *newer*: a higher version of the same line is offered, never another line (Opus never becomes Fable);
    - *gone*: a live list leaves it out, with that line's newest if there is one;
    - *unknown*: no list, or the engine's list leaves it out;
    - *follows*: a light reviewer that is the reviewer.
- **`devos models check [folder] [--apply]`:**
  - prints one line per role, then which roles would switch and the command for it;
  - `--apply` switches only those roles, each through `setModel` (`gh variable set DEVOS_<ROLE>_MODEL`, no commit);
  - it changes nothing without `--apply`, and refuses any other flag (exit 2).
- **The page.**
  - **The server:** `GET /api/models?check=1` adds `check` to the Models panel's answer, as model ids, statuses and
    notes only. Without `check=1` the answer is as before.
  - **The panel:** **Check for newer models** shows each role's result. **Use \<model\>** switches it through the
    existing `POST /api/models`.
- **`tools/models-refresh.mjs`** (for the engine's maintainer):
  - It reads the same live lists and prints, per tool, the newer models the engine's list lacks, and the models a live
    list no longer has.
  - `--write` adds the newer ones first in their family's group, and never removes one.
  - `dev/MAINTAINERS.md` has the steps.
- **Records:** the CHANGELOG entry `1.13.8 — Unreleased`; `README.md` (two rows); version 1.13.8 in `package.json`,
  `README.md` and `payload/manifest.json`; the tests that name the version (the upgrade scenarios now go from 1.13.8 to
  1.13.9).

### Limitations (reported)

1. **Grok, GPT and Gemini inside Cursor** are checked through Cursor's own list, so on the computer that runs the
   check the Cursor CLI must be installed and signed in. Otherwise the engine's list is used, and the check says so.
2. **A Claude Code subscription token** (`CLAUDE_CODE_OAUTH_TOKEN`) does not read Anthropic's models API: only an API
   key does. Without one, Claude Code is checked against the engine's list, which `tools/models-refresh.mjs` keeps
   current.
3. **The engine's list refresh is run by hand** (by you or the reviewer) and lands as a pull request. A scheduled run
   would need the providers' keys as secrets of the engine's repository; it is not part of this task.
4. **An id under Cursor's own prefix** (`cursor-grok-4.7-high`) is judged as a line of its own. The cycle's model
   choice does not run those ids either.
