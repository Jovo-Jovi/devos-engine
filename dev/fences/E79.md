  - **Every role starts empty.** This holds in the terminal (`devos init`, `devos adopt`) and on the guided page:
    - the reviewer, the light reviewer (the reviewer itself, or a model of its own), each builder;
    - the default builder when there are several, and who picks the builder for each task;

### Why these choices

- **One effort per run kind, not per risk.** A deep review, a method fix and the planning runs are the same agent
  at the same depth. A gate is the costliest call, so it has its own. The light reviews have theirs. That is three
  questions for the reviewer, never a table the developer must fill in.
- **`fence` is a choice, not a missing effort.** "The reviewer picks per task" was the old default. It is now
  something the developer says.
- **Stop, never substitute** (owner attention). A run that once fell back to `high`, `claude-opus-5-5`,
  `grok-4.7-high` or "the configured model" now stops with the key to set. Every existing project must answer
  `devos upgrade` once before its next cycle. From the project page, the upgrade asks you to run it in a terminal.
- **Out of scope:** the media module's own model ids (`media-providers/xai.mjs`: image, video and voice), and an
  effort field on **Another tool** (`devos models tool` names the keys to set when the new tool takes one).
