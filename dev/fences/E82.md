## E82 — Adopt from GitHub's main as it is now, and take its new commits before the push

(The owner, 2026-11-25, after learn-coptic's adoption pull request showed "This branch has conflicts that must be
resolved: docs/decisions.md, docs/glossary.md". The checkout's `main` was 9 commits behind GitHub's: devos adopted an
old copy, and GitHub's new commits had edited the two files devos moved aside. The owner: "Write fence E82 …: devos
adopt fetches the remote first and stops when the checkout's default branch is behind or has diverged from origin
(it names the commits and says to git pull), and adopt --publish stops before the push when origin's default branch
moved since the brief (it says to update the branch, or offers to merge origin into devos/adopt when git can do it
cleanly).")

- Phase: E · Risk: **2** · Gate: owner (your merge). Engine only: no file under `payload/files/` changes, so there is
  no precedent and no manual row. It changes:
  - **The survey fetches GitHub's main first** (`upstreamFacts`): `git fetch --quiet --no-tags origin
    +refs/heads/main:refs/remotes/origin/main`, then the local `main` against it. `survey.repository.upstream` is
    `{ state, behind, ahead, commits, error }`.
    - **behind:** a stop, `its main is 2 commits behind GitHub's (<sha> <subject>; …); run git pull, then devos adopt
      again`. At most five commits are named, then `and N more`.
    - **diverged:** a stop, `its main and GitHub's have diverged: 1 commit only here, 2 commits only on GitHub (…);
      bring them together (git pull, then git push what is only here), then devos adopt again`.
    - **ahead:** a note; the pull request carries those commits.
    - **failed:** a stop with git's reason, since the adoption pushes to GitHub at its end.
  - **Before the push, GitHub's new commits** (`catchUp`, the start of `adoptPublish`, before any key is asked). When
    GitHub's `main` moved since the brief:
    - **clean** (`git merge-tree --write-tree` says so): devos says so and asks **Merge them into devos/adopt?**. A yes
      merges them in the worktree (`Merge GitHub's main into devos/adopt`, without the project's hooks). The baseline
      is written again from the merged tree (nothing of it is on GitHub yet) and committed when it changed, then
      DEV_OS's checks run again. When a check fails or git cannot commit, the merge is undone and nothing is pushed.
    - **a no:** nothing is pushed; the branch stays as it was.
    - **conflicts:** nothing is pushed, and the files are named. So is a git older than 2.38, which cannot tell.

    The last lines give the merge by hand (`git switch devos/adopt`, `git merge origin/main` …, then
    `devos adopt --publish`) and the way to start again (`git pull`, `git branch -D devos/adopt`, a new brief).
  - **`devos adopt --publish` takes such a branch.** A `main` behind GitHub's no longer stops it, since `catchUp`
    handles that. devos's commit can be followed by the merge, or by the developer's own fix. The brief is found by
    its commit being one the branch grew from; before, it had to be the parent of the branch's last commit, which also
    missed a branch whose first commit moves files aside.
  - The origin's name comes from `remote.origin.url` as configured, and only then from `git remote get-url`, which
    applies `insteadOf` rewrites. `hubExec` returns `stderr` too, for git's reason.
  - **Tests:** `test/harness.mjs` `githubCopy` makes GitHub's stand-in for a project: a bare repository inside its
    `.git`, reached through the project's own `url.<copy>.insteadOf https://github.com/`. No test reaches the network.
    The adopt tests' projects get one (adopt, adopt-install, adopt-handover, ui-server).
  - The README, the changelog and the version, now **1.13.14**.

### Why these choices

- **Stop on behind, not pull for the developer.** devos never writes to the developer's `main`, and a pull can need
  their judgement (a merge, a rebase).
- **Merge into the branch before the push, not after.** The pull request then holds GitHub's `main`, so GitHub opens
  it without conflicts. GitHub's own check does not follow the moves into `docs/before-adopt/`; git's merge does.
- **Owner attention.** For learn-coptic, the steps given on 2026-11-25 (merge `origin/main` into `devos/adopt` by
  hand, then carry ADR-024 and النطق) still apply. E82 prevents the next one.
