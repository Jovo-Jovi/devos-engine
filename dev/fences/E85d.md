### The change

1. **One version order** in the new `lib/version.mjs`: a release is `X.Y.Z`, and a release candidate is
   `X.Y.Z-rc.N` (N from 1). Anything else, such as a beta, is neither. The order is
   `1.14.0-rc.1 < 1.14.0-rc.2 < 1.14.0-rc.10 < 1.14.0 < 1.14.1-rc.1`. `devos upgrade`, the project page (`lib/hub.mjs`,
   and the copy in `lib/ui/app.js`) and the release check all use it.
2. **`devos upgrade [--local] [--pre]`.**
   - An unknown or repeated option prints the usage, exit 2.
   - The project's lock and this engine may each be a release or a release candidate. Anything else stops with
     `devos: <where> names engine "<v>", which is neither a release (X.Y.Z) nor a release candidate (X.Y.Z-rc.N);
     devos upgrade runs between those`.
   - When this engine is a candidate and `--pre` is not given, it stops before anything changes:
     `devos: this engine is <v>, a release candidate; a test project takes it with devos upgrade --pre, and a project
     for real work stays on releases`.
   - A project on a candidate takes the release with a plain upgrade. An older engine is refused as before.
   - The branch is `devos/upgrade-<v>`, as before.
3. **The project page never upgrades a project to a release candidate.**
   - With a candidate engine, the upgrade action says `This engine is <v>, a release candidate: the page upgrades a
     project only to a release. For a test project, run devos upgrade --pre in its folder.`
   - The version row names the candidate and says how a test project takes it.
   - The page reads a project on GitHub whose lock names a candidate. GitHub's latest release is read only as a release
     (`releases/latest` never returns a prerelease).
4. **The release check** refuses a version that is neither, and on a candidate prints
   `release check: ok (N files scanned) · <v> is a release candidate: publish it as a prerelease, from next
   (dev/RELEASE.md)`.
5. **`next` until 1.14.0.**
   - D-E19 in `dev/DECISIONS.md`.
   - `dev/MAINTAINERS.md`: read `next` for `main` in "Running a task".
   - `dev/RELEASE.md`: a new *Release candidates* section.
   - `engine-ci` runs on `next` as on `main`, and every commit there keeps its own runs.
6. **Version 1.14.0-rc.1** in `package.json`, `README.md`, the manifest and `CHANGELOG.md` (`## 1.14.0-rc.1 —
   Unreleased`). The README's *Engine updates* explains release candidates, and its command row names `--pre`.
   - The tests that named the version now read it from `package.json`, except `version.test.mjs`. From now on, a
     candidate's bump changes only `package.json`, `README.md`, the manifest, `CHANGELOG.md` and `version.test.mjs`.
7. **Tests:**
   - the new `versions.test.mjs` holds the order, and the page's copy, to one table;
   - `upgrade.test.mjs` (E85d) ×3: a candidate only with `--pre`; a project on a candidate takes the release, never an
     older engine; the usage;
   - `release-check.test.mjs` (e);
   - `hub.test.mjs` (a) and (b); `hub-actions.test.mjs` (a) and (b). (e) now runs on a copy of this engine at a
     release, `9.0.0`, because the page upgrades only to a release;
   - `engine-ci.test.mjs` and `stability.test.mjs` (a) expect `next`.

26 files in all (24 changed, 2 new). Nothing changes for a project, and `devos upgrade` asks no question.
