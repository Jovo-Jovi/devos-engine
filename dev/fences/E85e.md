### The change

1. **A progress line a minute for every agent run, in the run's log** (`progress.sh`, rewritten). Nothing is posted.
   - The line is `<stage> · <tool> <model> · effort <label> · <minutes> min · <what>`.
   - `<what>` is:
     - for the builder: its files changed, its last action, and how long it has been quiet;
     - for a review: the review file's size;
     - for a plan: whether its answer is written;
     - otherwise `running`.
   - The effort's label comes from `effortLabel` in `builder-model.mjs`. An effort a model's name carries reads
     `xhigh, from the model name`. With no effort: `none: <tool> takes no effort`, or for Cursor `none: the model name
     names none`.
   - Who prints it:
     - the watchdog, every 60 seconds and at the end, for the builder of any tool (the tool from the command line:
       Cursor's CLI is `agent`);
     - `plan-agent.sh`, beside each run, for the review, intake and revise;
     - the supervisor's and the doctor's second-opinion steps.
   - What goes:
     - the work job's `Cursor is working` loop and the review job's 5-minute loop;
     - `builder-report.mjs`, which only the old progress comment read.
   - `plan-agent.sh`'s first line names the effort with the same label. So does the evidence pack's review plan, which
     read `effort ,`.
2. **GitHub's server errors are tried again** (`gh-retry.sh`, new):
   - publish (`devos-cycle.yml`) and advance (`devos-advance.yml`) install it first on their PATH, as `gh`;
   - an HTTP 5xx or a dropped connection is tried again after 10, 30 and 60 seconds, and a 4xx never is;
   - `gh pr create` first asks whether the try that failed made the pull request;
   - standard input is kept only when `gh` reads it;
   - publish's push (`publish-verify.mjs push`) retries the same way.
3. **Two supervisor rules, with no AI** (`supervisor.mjs`):
   - **`HTTP 5xx`**, in `gh`'s own wording, or the stand-in's last word: a cycle run stopped by it has its failed jobs
     re-run (`github-5xx`), so the review is kept. On main's `ci` it counts as an outside failure.
   - **A missing lockfile** (`ERR_PNPM_NO_LOCKFILE`, `npm ci` with no `package-lock.json`, or Yarn's forbidden lockfile)
     on main's `ci` is reported (🟡) with "Steps for you". Nothing is re-run and no AI is asked.
   - `classify` takes `--workflow ci|devos-deploy` and prints an incident's steps.
4. **D-E19 amended** for the owner's decision of 14:44: no live check per task, and E91 runs them all. `dev/RELEASE.md`
   and `dev/MAINTAINERS.md` follow. The version stays `1.14.0-rc.1`; `CHANGELOG.md` adds E85e's lines under it.
5. **The manual and PR-104.**
