### The change

1. **A topic comes from the task's own words** (`skills.mjs` `ownWords`, `fenceTopics`).
   - Left out: fenced code and inline code spans; paths and file names; the header lines (before the first section);
     a `Do NOT` section; every line that says "do not".
   - A `- Topics:` line still names a topic. A topic whose words are a header line (`launch`) is read from the headers.
   - `manifest.json`: payment's `checkout` becomes `checkout (pages?|sessions?|flows?|forms?|steps?)`.
2. **Only required files are read whole**, by the builder and the reviewer alike (`skillsBlock`, `readWhole`).
   - Read whole: each **required** file, and a skill's `DEVOS-NOTES.md` when that skill has a required file.
   - Every other file is listed after them, with what it covers, to open only when the change touches that.
   - `select --json` marks each file `read: whole` or `listed`; `INDEX.md` says so.
3. **A later attempt's review starts from the last one.**
   - Main's `publish-verify.mjs review-tree` writes `.devos/diff-since-a<N-1>.patch` on attempt N > 1. It holds the
     diff, its file list first, from the branch's last `Tnn a<N-1>: review` commit (first-parent line) to the head.
     It covers only the files the branch changes against main, now or at that review, so main's own changes stay out.
   - With no such commit, no file is written, and the log says the review reads the whole diff.
   - `render-prompt.mjs` adds the reviewer's `{{LATER_ATTEMPT_BLOCK}}` (new in `reviewer.md`) when the file is there:
     - judge each FAIL line of the last verdict and each point of the attempt focus against that diff;
     - a passed line stays PASS, citing that review, unless the diff touches what proved it;
     - every check ran again, so a red or missing required check fails the attempt;
     - read `.devos/diff.patch` only for context.
4. **The run says what the attempt used.**
   - `usage.mjs notice --task X --attempt N` prints one line: each stage's tool, model, runs, minutes and tokens, and
     the cost where it is known.
   - Publish's new step *What this attempt used*, after *Act on the verdict*, posts it as a notice. No AI call; with
     no record it prints a plain line.
5. **The fence writers** (`blueprint.md`, `intake.md`, `reviewer.md`) are told to add a `- Topics:` line for a topic
   their words do not name.
6. **The manual and PR-105:** `AUTOMATION.md` (`publish-verify.mjs`, `skills.mjs`, `usage.mjs` and the Layers
   paragraph); `PRECEDENTS.md` PR-105, live maximum PR-105; `CHANGELOG.md` under 1.14.0-rc.1.
