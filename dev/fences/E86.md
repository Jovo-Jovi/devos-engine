### The change

1. **One file per tool.**
   - `devos/agents/claude.json`, `cursor.json`, `codex.json` and `gemini.json` hold each tool's install, its command
     line per role, its effort (a flag, the model's name, or none), its output format, how it takes its prompt, its key
     names, its setup, its role kits and its local sign-in check.
   - Their schema is `devos/schemas/agent.schema.json`.
   - `scripts/devos/tools.mjs` (new) reads and checks them. Its commands are `ids`, `check`, `args`, `shell`, `setup`,
     `install`, `get`, `missing-key`, `of` and `slots`.
2. **One runner for the builder.**
   - `run-agent.sh` now runs every tool's builder, with the same steps: accounts, next models, the watchdog, one restart
     in place, server retries and limits.
   - Before, Claude Code's and Cursor's builder were two near-copies of that loop inline in `devos-work.yml`, and only
     Codex and Gemini used `run-agent.sh`. The work job's step is now one call.
   - `run-agent.sh`'s reviewer branch is gone: no workflow called it. Every review and plan runs through `plan-agent.sh`,
     which reads the registry too.
3. **The other scripts read the registry, so none names a tool:**
   - `install-agent.sh`, `pins.mjs`, `accounts.sh`, `role-env.mjs` and `agent-watchdog.sh`;
   - `agent-cli.mjs`, `agent-result.mjs`, `usage.mjs`, `render-prompt.mjs`, `lib.mjs`, `agents.mjs` and
     `builder-model.mjs`.

   In `accounts.sh`, `devos_tool`, `devos_accounts` and `devos_use <tool> N` replace `devos_use_<tool>` and
   `devos_prompt`. `role-env.mjs` takes `swap <tool> <role>`. The watchdog strips every tool's slots (`tools.mjs
   slots`), and runs nothing when it cannot read them.
4. **Two small fixes found while building:**
   - A builder run without its key names the tool and both accounts' secrets, for every tool. Before, only Cursor's
     message did; Claude Code's said "the _2 pair".
   - `plan-agent.sh`'s `watch_stop`: a stop lost while the progress watcher was starting left the run waiting for ever.
     It was seen once in this package's tests, under load; the same code has been there since E85e. The stop is now
     sent again until the watcher has ended, and a watcher still there after 5 s is ended with its sleep.
5. **The manual:**
   - `AUTOMATION.md`: the rows of `role-env.mjs`, `accounts.sh`, `plan-agent.sh`, `run-agent.sh`, `agent-cli.mjs`,
     `install-agent.sh`, `agent-watchdog.sh` and `pins.mjs`; a new `tools.mjs` row; the schemas line;
   - `PRECEDENTS.md`: PR-106, live maximum PR-106. It also says that the supervisor's and the doctor's second opinions
     and `loop.mjs` stay Claude Code until E87 (the design's G);
   - `CHANGELOG.md` under 1.14.0-rc.1;
   - `tools/sources.mjs` lists the six new payload files; the manifest has 369 files.
6. **Tests:**
   - `test/registry.test.mjs` (new):
     - (a) each tool, as builder, reviewer and planner, and its install, calls exactly what `next` @ 3ecf68a called: the
       same command, arguments, standard input, credential and role files. `test/agent-calls.mjs` (new) runs the work
       job's builder step, `plan-agent.sh` and `install-agent.sh` with stand-in CLIs; `test/fixtures/agent-calls.json`
       (new) is the base's record, made before any change;
     - (b) `tools.mjs check` and the schema's fields;
     - (c) `lib/data/tools.json` agrees with the registry;
     - (d) the ten account slots and the missing-key message;
     - (e) PR-99's refusal of a missing effort.
   - 15 tests changed where they read the old text, or ran the removed reviewer branch (those now run
     `plan-agent.sh`).

44 files in all (35 changed, 9 new). Nothing changes for a project: the same commands, keys, files and secret names,
and `devos upgrade` asks no question.
