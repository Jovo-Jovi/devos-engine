### The change

1. **What each tool can do (A).**
   - Each `devos/agents/<id>.json` gets `can`: some of `headless`, `edit` and `shell`. The four engine tools have all
     three. `tools.mjs check` refuses an unknown or repeated capability.
   - `tools.mjs` names each role's needs (`ROLE_NEEDS`): the builder and the reviewer all three, a planner `headless`
     and `edit`.
   - `agents.mjs` refuses a reviewer, a light reviewer or a pool builder whose tool cannot fill the role, and names
     what it lacks: `agents: reviewer is Echo agent, which cannot be the reviewer: it lacks shell
     (devos/agents/echo.json \`can\`)`.
2. **A project's own tool (B).** A project adds `devos/agents/<id>.json`, and anything it runs under
   `devos/agents/<id>/`. `tools.mjs` loads it beside the engine's tools.
   - **Output:** parser `contract`: the tool prints the agent output contract itself. `agent-result.mjs` already
     read that shape. Now `usage.mjs` reads its `usage`, and `limit-check.mjs` takes its `limited: true` as a limit.
   - **Install:** `none`, a command already on the runner. `install-agent.sh` checks that the command is there and
     installs nothing.
   - **Keys:** `DEVOS_AGENT_KEY` and `DEVOS_AGENT_KEY_2`. `tools.mjs secrets` now lists `DEVOS_AGENT_KEY` beside the
     engine tools' secrets, so every AI job's caller in `devos-cycle.yml` (work, review) and `devos-intake.yml`
     (intake, revise) names it literally, as E86b's rule requires.
3. **`devos agents check <id>` (C)**, in `lib/agents-check.mjs`, on your computer and with no AI call. It reports:
   - the file against the registry's rules, and the roles its `can` allows;
   - whether its command is on this computer;
   - whether the installed `devos-cycle.yml` passes its secret (and `_2`);
   - whether `devos.config.json` gives it a role it cannot fill.

   It exits 1 on any problem. A project's own file comes first, else the engine's copy.
4. **The docs (D).**
   - `AUTOMATION.md` §10 has a new recipe, *A new agent tool*: every field, the contract a `contract` tool prints,
     the fixed secrets, `devos agents check`, and a worked example of an OpenAI-compatible API script.
   - The rows of `agents.mjs`, `accounts.sh` · `limit-check.mjs`, `install-agent.sh` and `tools.mjs` say what changed.
   - `PRECEDENTS.md` has PR-109, live maximum PR-109. `CHANGELOG.md` has two lines under 1.14.0-rc.1.
5. **Tests:**
   - `test/capabilities.test.mjs` (new):
     - (a) the engine tools' `can`, the check of `can`, and `lacking`;
     - (b) a role given to a tool that cannot fill it is refused;
     - (c) in an installed project with its own tool `echo` (node running `devos/agents/echo/run.mjs`): it is loaded,
       its secret is `DEVOS_AGENT_KEY`, the installed callers name it, and its contract, usage and limit are read;
     - (d) `echo` reviews through `plan-agent.sh`: its key arrives under the name its script reads, no generic name
       reaches it, its answer and usage come from its contract, and a contract that says `limited` moves the run on;
     - (e) `devos agents check` on a ready tool, on a wrong secret and a missing capability, on a file the registry
       refuses, and on no file.
   - 4 tests changed where they list the AI secrets or the parsers.

24 files in all (22 changed, 2 new). For a project: the same secrets, plus `DEVOS_AGENT_KEY` only if it adds its own
tool; `devos upgrade` asks no question. The golden record of every tool's calls (`test/fixtures/agent-calls.json`)
is unchanged.
