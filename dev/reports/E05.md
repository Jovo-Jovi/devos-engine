### Deviations

A staged new file is still in the index after the worktree copy is deleted (`AD`). `rollback()` runs `git reset -q HEAD -- <add path>` before deleting that path, then restores, switches back, and deletes the empty branch. Without the reset, `git status --porcelain` is not empty after a failed commit of an added file.

The commit-failure test commits `hooks/pre-commit` before `git config core.hooksPath hooks`. An untracked hook makes the tree dirty, so upgrade refuses before `git commit`. Setting `core.hooksPath` first makes that setup commit fail. The hook then fails the upgrade commit. The test is skipped on Windows, as the fence says. It was run once on this machine with the skip turned off, and it passed; the skip is on in the file that was left.

`git reset` is the one command the fence's rollback list does not name. It is there so the stated result (a clean tree, no stray branch) holds when `git add` of a new file happened and `git commit` did not.
