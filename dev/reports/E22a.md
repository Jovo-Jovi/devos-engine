FIX 2. A body that parses to something other than a plain object answers 400: `/api/plan` with `The plan is not a JSON object.`, `/api/answer` with `The answer is not a JSON object.`. One try/catch wraps the request handler. On error it answers 500 `{"error":"internal"}` when headers are not sent, otherwise `res.destroy()`. It does not print the error.

FIX 3. `readFileKey` in `lib/keys.mjs`: when `read.interactive === true` and the trimmed line starts with `base64:`, it decodes the rest and returns the text when that text is JSON. On failure it prints `devos: <KEY>: the value given is not JSON` and asks again, inside the same three attempts. Any other line is still a path. The prompt is unchanged. `/api/answer` for a file key still checks that `value` decodes to JSON, then writes `base64:<value>` and a newline to the child's stdin. It does not write a key file. The value is dropped. `git grep -n "key-" -- lib/ui-server.mjs` prints nothing.

FIX 4. The checks run in order: Host, then Origin for a non-GET, then the token (`X-DEVOS-Token` on `/api/`, `?t=` on `GET /`). The body is read only after those checks. A refusal calls `req.resume()` before the answer, so the body is drained and not buffered. A body over 24 MiB without the token is 401.

FIX 5. With a child, `POST /api/stop` sets `stopping` and answers 204 at once. On Windows it calls `killPidTree` immediately. On POSIX it sends `SIGINT`, then an unref'd 2s timer calls `killPidTree` only if that child has not closed. The child's `close` clears the timer and emits `done` with code 130 when `stopping`. A `::devos-step {"step":"done"}` marker still emits its own code and a second done is not emitted. `stopping` is cleared at the next start. `close()` stops a live child the same way and waits for its `close`, at most 3s, then ends subscribers, closes the server, and removes the temp folder.

FIX 6. Test (m) builds the plan with `planFrom` on a normal stage and runs the server on a separate hang stage. It stays skipped on Windows.
