`POST /api/clone` takes an optional `adopt`: true clones a repository whose default branch has no engine lock, and refuses one that already has the lock.

`POST /api/adopt/check` surveys one full path, in choose mode and while no run is going, and returns the survey and its lines, or the folder or git error, without starting `devos adopt`.

`POST /api/adopt/start` checks the optional AI tool and the folder, then starts `devos adopt` for that folder and answers 202.

`GET /api/state` returns `runKind`: `init` after a new-project start, `adopt` after an adoption start, and null before any run.

`POST /api/answer` accepts `kind: "line"` and writes that one line to the run; a value that contains a newline is refused.

The machine screen, in choose mode, offers Existing project, and Add DEV_OS opens the adopt screen when the same doctor check that gates Current project passes.

The adopt screen, titled Add DEV_OS to your project, takes a folder on this computer or a GitHub address, shows the survey, and starts the brief when the survey is ready.

The adopting screen, titled Adding DEV_OS, shows the run's log, the line and key questions, and whether DEV_OS was added.

### Deviations

With `adopt: true`, a clone that lands is accepted when the folder exists. `resumePoint(target).started` would refuse every repository that has no engine lock, which is the repository adoption is for. Without `adopt`, that check is unchanged. The owner or admin check, the folder and reuse are unchanged.

`POST /api/continue` sets `runKind` back to null, so a continue is not opened as the adopting screen. The fence names null before any run.

The folder control uses the system's folder dialog and a pasted full path. It does not use `folderFinder`, which looks up a project that already has DEV_OS.

The pull-request pattern is the regex literal in `lib/ui/app.js`. A comment with the unescaped `https://github\.com` form failed `ui-page.test.mjs` (d), which only allows an address that starts with `https://github.com/`.

`git diff --name-only main` also lists `dev/LEDGER.md` and `dev/fences/E39.md`. Those are the reviewer's commit `c7eca7e` (fence v1), on the branch before the first edit. This attempt did not change them.

The new routes answer `The request is not JSON.` and `The request is not a JSON object.` for a bad body, as the other routes do. The fence does not name those two sentences.

The adopt screen adds short hints the fence does not name: the empty-Send hint, the section titles, and the lede. The required titles, button texts, descriptions and result sentences are the fence's.

Quick buttons are one set: `(yes/no)` or `Type yes or no`, else `Type yes to`, else `Type accept`, else `Choose 1 or 2`.
